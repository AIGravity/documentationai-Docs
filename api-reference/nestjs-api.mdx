## Overview

The NestJS API service exposes endpoints across several controllers: health, connections, marketplace, apps, and legacy deprecated routes. Protected endpoints require a Supabase Bearer JWT token and enforce authentication before controller logic runs.

<Callout kind="info">

Implementation details on this page were derived from code analysis of the API service controllers.


</Callout>

<Callout kind="alert">

The repository README mentions `GET /api/health`, but the code currently implements `GET /health`. No global prefix is configured, so the `/api` path is not active.


</Callout>

## Likely error responses

The analyzed code does not define custom error handling for this route. The most likely responses are framework-level errors.

### 404 not found

A `404` response is likely when you request the wrong path or use the wrong HTTP method. For example, `GET /api/health` or `POST /health` would not match the implemented route.

### 500 internal server error

A `500` response is only likely if the NestJS framework or runtime fails while serving the request. No route-specific error branches were found in the analyzed handler.

## Notes

The NestJS bootstrap code enables CORS for origin `http://localhost:3000` and sets `credentials` to `true`. The application listens on port `3001`, so the health endpoint is available at `http://localhost:3001/health` in the current local configuration.

## Connections

### POST `/api/connections/auth/apps`

Use this endpoint to retrieve the list of Composio apps referenced in a workflow object.

<ParamField body="method" param-type="string" required="true" show-location="false">

`POST`


</ParamField>

<ParamField body="path" param-type="string" required="true" show-location="false">

`/api/connections/auth/apps`


</ParamField>

<ParamField body="auth" param-type="string" required="true" show-location="false">

Bearer JWT enforced by `SupabaseAuthGuard`.


</ParamField>

<ParamField body="workflow" param-type="object" required="true" show-location="false">

Workflow object to inspect for referenced Composio apps.


</ParamField>

<CodeGroup tabs="cURL,JSON">

```bash
curl -X POST http://localhost:3001/api/connections/auth/apps \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.example" \

  -d '{
    "workflow": {
      "nodes": [

}
```

</CodeGroup>

<ResponseField name="apps" field-type="string[]" required="true">

List of Composio app slugs referenced in the submitted workflow.


</ResponseField>

### GET `/api/connections/auth/connections`

Use this endpoint to list all Composio connections for the authenticated user.

<ParamField body="method" param-type="string" required="true" show-location="false">

`GET`


</ParamField>

<ParamField body="path" param-type="string" required="true" show-location="false">

`/api/connections/auth/connections`


</ParamField>

<ParamField body="auth" param-type="string" required="true" show-location="false">

Bearer JWT enforced by the authenticated connections controller.


</ParamField>

<ParamField body="request body" param-type="none" required="false" show-location="false">

None. This endpoint does not accept a request body.


</ParamField>

<Callout kind="info">

Returned statuses are normalized before they reach the client. `connected` maps to active connections, `needs_reconnect` maps to expired, failed, or inactive connections, and `INITIATED` or `INITIALIZING` states are omitted. On any internal error, the endpoint returns `{"connections": []}` instead of throwing.


</Callout>

<CodeGroup tabs="cURL,JSON">

```bash
curl http://localhost:3001/api/connections/auth/connections \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.example"
```

```json
{
  "connections": [
    {
      "slug": "gmail",
      "status": "connected",
      "connectionId": "cnx_2sKd9Qm1"
    },
    {
      "slug": "slack",
      "status": "needs_reconnect",
      "connectionId": "cnx_4bTr8Vz7"
    }
  ]
}
```

</CodeGroup>

<ResponseField name="connections" field-type="object[]" required="true">

List of normalized Composio connections for the authenticated user.


</ResponseField>

<ResponseField name="slug" field-type="string" required="true">

App slug for a connection entry.


</ResponseField>

<ResponseField name="status" field-type="string" required="true">

Normalized connection status. The response uses `connected` or `needs_reconnect`.


</ResponseField>

<ResponseField name="connectionId" field-type="string" required="true">

Connection identifier for the app entry.


</ResponseField>

#### Error responses

A `401` response indicates that authentication is required or the Bearer token is invalid.

## Marketplace

### POST `/api/marketplace/builder-fields`

Use this endpoint to resolve builder fields for a published workflow from consumer inputs.

<ParamField body="method" param-type="string" required="true" show-location="false">

`POST`


</ParamField>

<ParamField body="path" param-type="string" required="true" show-location="false">

`/api/marketplace/builder-fields`


</ParamField>

<ParamField body="auth" param-type="string" required="true" show-location="false">

Bearer JWT required for marketplace builder field resolution.


</ParamField>

<ParamField body="agentId" param-type="string" required="false" show-location="false">

Published agent identifier used to resolve consumer-input-backed builder fields.


</ParamField>

<Callout kind="info">

Each builder field can include a `targets` array that binds a consumer input to one or more workflow node parameters. That mapping is the link between the published workflow definition and the values a consumer supplies at runtime.


</Callout>

<CodeGroup tabs="cURL,JSON">

```bash
curl -X POST http://localhost:3001/api/marketplace/builder-fields \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.example" \
  -H "Content-Type: application/json" \
  -d '{
    "agentId": "agent_9vK2mLp4"
  }'
```

```json
{
  "fields": [
    {
      "id": "bf_01J8Z7KQ4H3T",
      "engine": "n8n",
      "canonicalName": "recipient_email",
      "fieldType": "short-text",
      "label": "Recipient email",
      "required": true,
      "defaultValue": null,
      "pieceName": "gmail",
      "pieceVersion": "1.2.0",
      "actionName": "send_email",
      "propertyName": "to",
      "refreshers": [],
      "targets": [
        {
          "nodeName": "Send welcome email",
          "paramPath": "parameters.to"
        }
      ],
      "staticOptions": null,
      "markdownValue": null
    }
  ],
  "source": "ap-consumer-inputs"
}
```

</CodeGroup>

<ResponseField name="fields" field-type="array" required="true">

Resolved builder fields for the published workflow. Each array item includes `id`, `engine`, `canonicalName`, `fieldType`, `label`, `required`, `defaultValue`, `pieceName`, `pieceVersion`, `actionName`, `propertyName`, `refreshers`, `targets`, `staticOptions`, and `markdownValue`.


</ResponseField>

<ResponseField name="source" field-type="string" required="true">

Resolution source for the response. The analyzed controller returns `ap-consumer-inputs`, `no-agent-id`, or `no-ap-row`.


</ResponseField>

#### Error responses

A `401` response indicates that authentication is required or the Bearer token is invalid.
