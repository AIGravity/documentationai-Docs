## Overview

This page documents the NestJS backend service routes currently implemented in the AIGravity core repository. The code analysis found two public endpoints: `GET /health` and `POST /api/chat/message`.

<Callout kind="info">

Implementation details on this page were derived from code analysis of `apps/api/src/main.ts`, `apps/api/src/app.module.ts`, and related route and DTO files in the AIGravity core repository, rather than direct file reads through the docs repository tool.


</Callout>

<Callout kind="alert">

The repository README mentions `GET /api/health`, but the code currently implements `GET /health`. No global prefix is configured, so the `/api` path is not active for the health route.


</Callout>

### nextStep routing

The `nextStep` field tells the client which screen or flow to transition to after each chat turn.

- **`intent`** — Continue the clarifying conversation to gather more details.
- **`tools`** — Show the tool selection screen so the user can pick which tools they use.
- **`agents`** — Show the agent carousel with matched agents from the search results.
- **`no_agents`** — Route to the bounty or request-an-agent path when no matching agents are found.

<Callout kind="info">

When the AI service returns `nextStep: "agents"` but all enriched agent results are stale and no matching active published workflows exist in the database, the API now re-routes `nextStep` to `no_agents` instead of showing an empty agent carousel. This prevents the client from rendering an empty results screen and sends the user directly to the request-an-agent flow.


</Callout>

## Likely error responses

The analyzed code does not define custom error handling for the health route. The chat endpoint can also return validation and downstream-service failures.

### 400 bad request

A `400` response is returned when the request body fails validation. One likely example is a `message` value longer than 4000 characters.

### 404 not found

A `404` response is likely when you request the wrong path or use the wrong HTTP method. For example, `GET /api/health` or `POST /health` would not match the implemented route.

### 500 internal server error

A `500` response is returned when the AI service call fails or an unexpected error occurs during chat processing. The health route would only return `500` if the NestJS framework or runtime fails while serving the request.

### 503 service unavailable

A `503` response is returned when the downstream AI service is unreachable.

## Notes

The NestJS bootstrap code enables CORS for origin `http://localhost:3000` and sets `credentials` to `true`. The application listens on port `3001`, so the health endpoint is available at `http://localhost:3001/health` in the current local configuration.
