## Overview

Authenticate users, publish agents, run marketplace workflows, manage automations, process billing and payouts, and integrate third-party connections through the NestJS API.

The API listens on port `3001` by default. Most routes use the `/api` prefix applied at the controller level. The application does not apply `/api` as a global prefix.

Protected endpoints use JWT bearer authentication. Include the token in the `Authorization` header:

```http
Authorization: Bearer <token>
```

DTO-validated endpoints reject unknown request body properties with a `400` response. Admin endpoints require both a valid bearer token and administrator authorization.

## Authentication

<ParamField header="Authorization" param-type="string" required="true">

JWT bearer token for protected endpoints. Format: `Bearer <token>`.

</ParamField>

### Common error responses

<ResponseField name="400" field-type="object">

Validation failure or invalid input, such as an invalid UUID or a missing required field.

</ResponseField>

<ResponseField name="401" field-type="object">

The request does not include a valid authentication token.

</ResponseField>

<ResponseField name="403" field-type="object">

The authenticated user does not have sufficient permissions, such as when a non-admin accesses an admin route.

</ResponseField>

<ResponseField name="404" field-type="object">

The requested resource does not exist.

</ResponseField>

<ResponseField name="409" field-type="object">

The request conflicts with existing data, such as an email address that is already registered.

</ResponseField>

<ResponseField name="422" field-type="object">

The request is syntactically valid but cannot be completed semantically, such as when a marketplace trigger cannot be enabled.

</ResponseField>

<ResponseField name="500" field-type="object">

An unexpected server error. The global exception filter sanitizes the response before returning it to the client.

</ResponseField>

### POST `/api/auth/login`

Authenticate with an email address and password.

<ParamField body="email" param-type="string" required="true">

User email address.

</ParamField>

<ParamField body="password" param-type="string" required="true">

User password.

</ParamField>

<ResponseField name="user" field-type="object" required="true">

User profile information.

</ResponseField>

<ResponseField name="accessToken" field-type="string" required="true">

JWT access token for protected API requests.

</ResponseField>

<ResponseField name="refreshToken" field-type="string" required="true">

Refresh token used to obtain a new access token.

</ResponseField>

<ResponseField name="isNewUser" field-type="boolean" required="false">

Indicates whether the authentication flow created a new user. OTP endpoints may include this field.

</ResponseField>

<CodeGroup tabs="cURL,JSON">

```bash
curl -X POST http://localhost:3001/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "email": "jane.chen@acme.test",
    "password": "S3cureExamplePassword!"
  }'
```

```json
{
  "user": {
    "id": "usr_a1b2c3d4",
    "email": "jane.chen@acme.test",
    "name": "Jane Chen"
  },
  "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.example.access",
  "refreshToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.example.refresh",
  "isNewUser": false
}
```

</CodeGroup>

### POST `/api/marketplace/run`

Start a marketplace workflow run.

<ParamField body="workflowId" param-type="string" required="true">

Identifier of the workflow to run.

</ParamField>

<ParamField body="input" param-type="object" required="true">

Input values required by the workflow.

</ParamField>

<ParamField body="consumerCopyId" param-type="string" required="false">

Optional consumer workflow copy identifier.

</ParamField>

<ResponseField name="runId" field-type="string" required="true">

Identifier used to poll the run result.

</ResponseField>

<ResponseField name="status" field-type="string" required="true">

Run state. Long-running runs can return `running` or `pending`.

</ResponseField>

<Callout kind="info">

Long-running runs return a running or pending handle instead of blocking. Poll `/api/marketplace/run-result` or `/api/marketplace/test-builder/run-result` for completion. ActivePieces `QUEUED` runs are represented as `running`, not as errors.

Trigger-enable failures return `422` with actionable engine details. The `activate` endpoint can return the same `422` response when enabling a trigger fails.

</Callout>

### POST `/api/subscriptions/checkout`

Create a checkout session for a paid subscription plan.

<ParamField body="planId" param-type="string" required="true">

Identifier of the plan to purchase.

</ParamField>

<ParamField body="successUrl" param-type="string" required="true">

URL to redirect to after successful checkout.

</ParamField>

<ParamField body="cancelUrl" param-type="string" required="true">

URL to redirect to when checkout is canceled.

</ParamField>

<ResponseField name="checkoutUrl" field-type="string" required="true">

URL for the hosted checkout session.

</ResponseField>

<Callout kind="info">

`/api/subscriptions/current` returns `404` with `NO_ACTIVE_SUBSCRIPTION` when the user has no active subscription. Subscribing with an invalid plan ID returns `PLAN_NOT_FOUND`.

Paid plans require checkout. A direct request to `/api/subscriptions/{planId}` returns `400` with `PAID_PLAN_REQUIRES_CHECKOUT`; use `/api/subscriptions/checkout` instead. Plans endpoints return `404` when the billing feature flag is disabled.

</Callout>
