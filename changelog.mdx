## Overview

This changelog tracks notable product changes that affect end users. Entries are organized as new features, updates, and bug fixes — newest first.

## September 2026

<Update date="2026-09-07">

### New features

- **Agent review pipeline** — Admin reviewers now see test-run output in plain language instead of raw JSON. Approved agents retain their execution history, and builder answers survive failed test runs so they can be restored on retry. Failed runs receive a clear diagnosis (platform, connection, workflow, setup, or unknown) with actionable guidance instead of opaque error text.
- **Billing and subscriptions** — A new admin billing dashboard shows revenue, margins, payouts, and per-user views. Creators can track earnings and withdrawable balances. Subscription checkout is region-routed: India uses Razorpay and other regions use Stripe. Subscriptions include usage quotas and reserved capacity for scheduled agents.
- **Referral earnings** — Builders can earn referral revenue and track it through a dedicated earnings panel.

### Updates

- **Smarter Activepieces compatibility** — Gravity now detects the installed Activepieces version and only applies compatibility workarounds when needed. Newer versions skip obsolete shims automatically, and AI provider values from both old and new formats are accepted.
- **Clearer run status** — Paused runs are now classified as approval, delay, AI-agent work, or unknown — instead of always showing "waiting for approval." Memory-limit, log-size, and quota failures appear as real failures with diagnostic messages. Timeout runs retain their failed-step details.
- **Cheaper AI model routing** — Expensive AI models are automatically replaced with cheaper same-vendor alternatives based on live pricing during marketplace runs.

### Bug fixes

- **Approval-paused runs no longer fail early** — Workflows waiting for approval stay in a paused state instead of appearing to fail immediately. Polling continues for up to two hours in the builder and 24 hours for reattachment.
- **Recurring agents stay tracked while paused** — A regression that caused approval-paused recurring runs to lose their active run handle has been fixed. Temporary network errors no longer reset the poller to an aggressive three-second interval.
- **Email lookups are case-insensitive** — Mixed-case or whitespace-different email addresses no longer cause account provisioning or invitation lookup failures.
- **File proxying is scoped to your Activepieces instance** — File URLs are only proxied when they come from your configured Activepieces host. Third-party URLs that happen to contain `/api/v1/files/` are left untouched, preventing broken downloads.
- **AI steps from Activepieces Cloud import correctly** — Provider objects exported from newer Activepieces Cloud versions no longer become `[object Object]` and fail on the first AI call. Both string and object provider formats are now accepted.
- **Unsupported action versions are caught early** — Actions built against newer Activepieces versions are pinned to the newest compatible installed version when possible, or rejected before execution with a message naming the affected step, app, and version gap.
- **Empty dropdown responses no longer crash the builder** — Empty Activepieces responses are converted to readable errors instead of causing JSON parse failures. Non-dynamic fields no longer trigger unnecessary options lookups.
- **NUL bytes in workflow JSON no longer block submissions** — Agent submissions containing stray NUL characters are now cleaned before persistence, preventing a misleading error about Supabase configuration.

</Update>
