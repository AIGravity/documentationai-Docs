## Agent quality scoring and review-gated publishing

PR #195 introduces automated quality scoring for agent submissions and makes admin review mandatory for all publishing paths.

### Review-gated publishing

All agent publishing paths now follow the same review flow. Regular publish, bounty, and requested-agent submissions all go to an admin review queue and require human approval before they go live.

The builder call to action changed from `Publish your agent` to `Submit for review`. The builder dashboard also now shows a simplified `In review` status for all pending submissions.

<Callout kind="alert">

This changes the publishing flow for every submission path. If your team expected agents to become live immediately after submission, update internal workflows to account for the required review step.


</Callout>

### Automatic quality scoring

A new agent-ranker scoring service evaluates each agent when you submit it for review. The service produces a `0` to `100` quality score based on output quality, reliability, speed, and cost.

If `AGENT_RANKER_MIN_SCORE` is configured, the platform automatically rejects agents that score below the threshold and never sends them to the admin queue. If the ranker service is unreachable or the threshold is not configured, the platform sends all submissions to the admin review queue.

### API changes for POST /agents/submit-for-review

`POST /agents/submit-for-review` now accepts additional scoring context and can return either a pending or rejected outcome.

<ParamField body="testRunId" param-type="string" required="false" show-location="false">

Pre-submit end-to-end test run ID used for quality scoring. Maximum length: `64` characters.


</ParamField>

<ResponseField name="status" field-type="string" required="true">

Submission status. Now returns `pending` or `rejected`. Previously returned `pending` only.


</ResponseField>

<ResponseField name="rankerScore" field-type="number | null" required="true">

Quality score from `0` to `100`. Returns `null` when scoring does not run or does not complete.


</ResponseField>

<ResponseField name="rejectedReason" field-type="string" required="false">

Present only when the platform auto-rejects the submission for scoring reasons. Current value: `below_quality_threshold`.


</ResponseField>

### New configuration variables

<ParamField body="AGENT_RANKER_MIN_SCORE" param-type="number" required="false" show-location="false">

Minimum quality score required for a submission to enter the admin review queue. When set, the platform auto-rejects submissions below this threshold.


</ParamField>

<ParamField body="AGENT_RANKER_API_URL" param-type="string" required="false" show-location="false">

Base URL of the ranker scoring service.


</ParamField>

### Data model changes

This release adds new scoring metadata to review and publishing records so admins can inspect submission quality and test evidence during review.

- New ranker score columns: `ranker_score`, `ranker_scores`, `ranker_bundle_version`, and `ranker_scored_at`
- Columns were added to published workflow metadata, pending agent reviews, and rejected agent reviews tables
- New E2E test runs table stores pre-submit test run results for scoring and admin review


</Update>
