## Overview

Gravity persists platform data through Supabase (PostgreSQL) and integrates with Activepieces' Postgres for workflow and run data. The data model spans identities, agents, marketplace workflows, billing, earnings, referrals, bounties, reviews, and connections.

<Callout kind="info">

This reference describes the domain entities and their relationships from a user-facing perspective. It does not enumerate every database column. The focus is on the entities that users interact with through the API.

</Callout>

## Entity overview

| Domain area | Key entities | Description |
| --- | --- | --- |
| Identity and profiles | Users, profiles, builder profiles | Account types such as creator and business, onboarding data, and builder-specific settings |
| Agents | Published agents, review submissions | Agent listings, verification state, review findings, and feedback |
| Marketplace | Published workflows, consumer copies, runs | Agent catalog, consumer workspace clones, and execution records |
| Subscriptions | Plans, subscriptions, cycles, entitlements | Billing plans, active subscriptions, billing cycles, and credit state |
| Earnings | Earnings balance, payouts, payout accounts | Creator revenue, withdrawal requests, and payout destinations |
| Referrals | Share links, referral attributions, earnings | Referral codes, click tracking, and monthly settlement records |
| Bounties | Bounties, submissions | Funded requests, builder entries, and award records |
| Requested agents | Requests, interests | Agent requests and interest tracking |
| Connections | App connections, OAuth tokens, API keys | External service connections and credentials |
| Reviews | Review findings, builder feedback, evidence scores | Quality review results, builder responses, and scoring data |

## Identity and profiles

Identity records establish who uses Gravity and how each account participates in the platform.

- **Users**: An account with an email address, an account type of creator or business, and an authentication method such as password, OTP, or Google OAuth.
- **Profiles**: Onboarding data including full name, industry, profession, and the automations the user has built.
- **Builder profiles**: Builder-specific settings including payout currency and referral code.

## Agents and marketplace

Marketplace entities connect published agents with the workflows consumers activate and run in their workspaces.

- **Published agents**: Agent listings with a name, description, workflow template, tags, categories, and consumer input schema.
- **Review submissions**: Agent submissions with verification state, review findings, and builder feedback.
- **Consumer copies**: Cloned agent instances in a consumer's workspace with activation state and schedule configuration.
- **Runs**: Execution records with status, result data, paused-run kind, and error classification.

<Callout kind="info">

Paused runs carry a `kind` field that classifies the pause reason: `approval`, `delay`, `agent`, or `unknown`. Failed runs distinguish resource errors such as memory, log size, and quota issues from timeout and general execution errors.

</Callout>

## Subscriptions and billing

Billing entities track the plan a user selects, the subscription lifecycle, and the credits available for agent execution.

- **Plans**: Subscription tiers with pricing, currency, and included credits.
- **Subscriptions**: An active subscription with status, plan, renewal date, and cancellation flag.
- **Cycles**: A monthly billing cycle with start and end dates.
- **Entitlements**: Credit state including ledger credits, outstanding holds, spendable credits, and reserved budget.
- **Reservations**: Soft credit reservations for scheduled agents.

## Earnings and payouts

Earnings entities track creator revenue and the movement of funds from earned balances to payout destinations.

- **Earnings balance**: The withdrawable amount, pending payouts, and currency associated with a creator.
- **Payouts**: Withdrawal requests with amount, currency, destination, and provider status.
- **Payout accounts**: Bank, UPI, PayPal, or Stripe Connect destinations with masked identifiers.

## Referrals

Referral entities connect shared agent links to referred users and the earnings generated through those referrals.

- **Share links**: Referral codes associated with agents.
- **Referral attributions**: Links between referred users and referrers, including click tracking.
- **Referral earnings**: Monthly settlement records for first-year earnings generated by referred builders.

## Bounties

Bounties let users fund requests and builders submit agents or workflows in response.

- **Bounties**: Funded requests with title, amount, currency, and funding state.
- **Submissions**: Builder entries with workflow, agent name, and review status.

## Review and quality

Review entities capture the findings, builder responses, and evidence used to assess agent quality.

- **Review findings**: Individual findings with severity, title, message, and builder verdict of fair or unfair.
- **Builder feedback**: A verdict and notes submitted by builders on individual findings.
- **Evidence scores**: Multi-axis scoring across behavioral, code, network, guardrail, and AI-reviewer dimensions.

## Connections

Connection entities represent the external tools that agents use and the health of those integrations.

- **App connections**: OAuth and API key connections with provider, status, and associated agent references.
- **Connection health**: Status tracking for connected tools and the agents affected by disconnections.

## Persistence

Gravity uses Supabase (PostgreSQL) as its primary persistence layer. Supabase stores identities, profiles, agents, marketplace workflows, billing records, earnings, referrals, bounties, review state, and connections.

The platform also reads from Activepieces' Postgres database for workflow and run data, including flow state, run results, and execution metadata.

<Callout kind="info">

Scheduled-agent reservations are soft reservations. They hold credits during the billing cycle and release them when the schedule is paused or the subscription is cancelled.

</Callout>
