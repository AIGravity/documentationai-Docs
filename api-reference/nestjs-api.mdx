## Overview

This page documents the NestJS backend service route currently implemented in the AIGravity core repository. The code analysis found a single public endpoint: `GET /health`.

<Callout kind="info">

Implementation details on this page were derived from code analysis of `apps/api/src/main.ts`, `apps/api/src/app.module.ts`, and `apps/api/src/health/health.controller.ts`, rather than direct file reads through the docs repository tool.

</Callout>

<Callout kind="alert">

The repository README mentions `GET /api/health`, but the code currently implements `GET /health`. No global prefix is configured, so the `/api` path is not active.

</Callout>

## Response

A successful request returns `200 OK` with a JSON object that identifies the service and reports its status. NestJS serializes the plain object returned by the handler as `application/json`.

### Response fields

<ResponseField name="status" field-type="string" required="true">

</ResponseField>

<ResponseField name="service" field-type="string" required="true">

</ResponseField>

## Likely error responses

The analyzed code does not define custom error handling for this route. The most likely responses are framework-level errors from NestJS.

### 404 not found

A `404` response is likely when you request a path or method combination that does not match the implemented route. For example, `GET /api/health`, `GET /unknown`, or `POST /health` would not match `GET /health`.

The example below shows the framework-level response shape for `POST /health`. The `message` value changes based on the requested method and path, such as `Cannot GET /unknown` for an unmatched `GET` request.

```json
{
  "statusCode": 404,
  "message": "Cannot POST /health",
  "error": "Not Found"
}
```

### 500 internal server error

A `500` response is only likely if the NestJS framework or runtime fails while serving the request. No route-specific error branches were found in the analyzed handler.

```json
{
  "statusCode": 500,
  "message": "Internal server error"
}
```

## Notes

The NestJS bootstrap code enables CORS for origin `http://localhost:3000` and sets `credentials` to `true`. The application listens on port `3001`, so the health endpoint is available at `http://localhost:3001/health` in the current local configuration.
