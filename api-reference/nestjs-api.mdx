## Overview

The NestJS API is Gravity's primary backend for agent publishing and review, marketplace workflow execution, subscription billing, credits, earnings, referrals, and payouts.

The default local base URL is `http://localhost:3001`. Configure the listening port with the `PORT` environment variable. The API does not use a global URL prefix. Controllers define their own `/api/...` route prefixes.

CORS origins are configured with the `CORS_ORIGINS` environment variable. The default origins are:

- `http://localhost:3000`
- `http://localhost:5173`
- `http://localhost:5174`

<Callout kind="info">

Request validation uses a global validation pipe. Unknown properties are stripped from request bodies, and input types are transformed when the endpoint's validation rules support transformation.

</Callout>

## Authentication

Most endpoints require a Supabase bearer token. Send the token in the `Authorization` header.

```http
Authorization: Bearer eyJhbGciOiJIUzI1NiIs.eyJzdWIiOiJ1c2VyX2V4YW1wbGUifQ.signature
```

Admin endpoints require both an authenticated user and an administrator role. Public endpoints do not require a bearer token.

Public endpoints include:

- Health checks
- Public workflow detail
- Share-link resolution
- File proxy downloads
- Webhook receivers

Webhook endpoints authenticate through provider signature verification instead of bearer tokens.

## Health

### GET `/`

Returns the API service status. This endpoint is public.

```json
{
  "status": "ok",
  "service": "api"
}
```

### GET `/health`

Returns the API service status and the current server timestamp. This endpoint is public.

```json
{
  "status": "ok",
  "service": "api",
  "timestamp": "2025-01-15T10:30:00.000Z"
}
```

</Callout>

## Subscriptions

All subscription endpoints require authentication. Subscription operations are feature-flagged and return `404` when billing is disabled.

| Method | Route | Description |
| --- | --- | --- |
| GET | `/api/subscriptions/plans` | List available plans. Returns `{ "plans": [...] }`. |
| GET | `/api/subscriptions/current` | Get the current subscription. Returns `status`, `plan`, `renewsAt`, and `cancelAtPeriodEnd`. Returns `404` when no active subscription exists. |
| GET | `/api/subscriptions/entitlement` | Get entitlement state, including `ledgerCredits`, `outstandingHolds`, `safetyNet`, `spendableCredits`, `activeBudget`, and `reservedBudget`. |
| GET | `/api/subscriptions/history` | Get subscription history. Returns entries containing `plan`, `status`, `startedAt`, and `canceledAt`. |
| POST | `/api/subscriptions/checkout` | Start checkout for a paid plan. The body includes `planId` and optional `countryOverride`. Returns `201` with `checkoutUrl`, `providerSessionId`, and `expiresAt`. |
| POST | `/api/subscriptions/cancel` | Cancel a subscription at the end of the current period. Returns `status`, `effectiveDate`, and `message`. |
| POST | `/api/subscriptions/:planId` | Activate a free plan. Returns `201` with `subscriptionId`, `plan`, `status`, and `cycleId`. Paid plans must use checkout. |
| GET | `/api/billing/plans` | Alternative endpoint for listing plans. Returns `{ "plans": [...] }`. |

<Callout kind="info">

Checkout selects Razorpay for users in India and Stripe for international users based on geographic detection. Activate free plans directly. Paid plans require checkout.

</Callout>

## Run status semantics

Workflow runs use four states:

- `running`: The run is currently executing.
- `paused`: The run is still in progress but is waiting for an external condition.
- `succeeded`: The run completed successfully.
- `failed`: The run stopped because an error or limit prevented completion.

A paused run is not terminal. Paused runs include a `kind` field with one of these values:

- `approval`
- `delay`
- `agent`
- `unknown`

The API treats provider `QUEUED` status as `running`. Memory limit errors, log size errors, and quota exceeded conditions are reported as `failed`, while preserving the provider's failure message.

Timeout responses retain details about the failed step. Unsupported action-piece versions produce a readable `422` response that identifies the step, application, action, and version gap.

## Examples

### Health check

```bash
curl -i http://localhost:3001/health
```

### List available workflows

```bash
curl -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIs.eyJzdWIiOiJ1c2VyX2V4YW1wbGUifQ.signature" \
  http://localhost:3001/api/marketplace/workflows
```

### Start a workflow run

```bash
curl -X POST \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIs.eyJzdWIiOiJ1c2VyX2V4YW1wbGUifQ.signature" \
  -H "Content-Type: application/json" \
  -d '{"publishedWorkflowId":"wf_7f4a2c91e6b84d0f","input":{"customerId":"cus_28a91f6e"}}' \
  http://localhost:3001/api/marketplace/run
```
