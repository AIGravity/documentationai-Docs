## Overview

Manage your own agents, submit them for verification, track review status, and administer running automations from the same API surface. All endpoints on this page require a Bearer JWT, and admin endpoints require a token with admin access.

<Callout kind="info">

Add your JWT in the `Authorization` header as `Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.example`.


</Callout>

## Agent ownership endpoints

Fetch one of your own agents by ID. If the agent does not exist or belongs to a different builder, the API returns the same `404` response to prevent ID probing.

## Verification endpoint

### POST `/api/agents/verify-stream`

Submit an agent for verification and receive progress updates over server-sent events. Use this endpoint when you need automated checks to run immediately and want a streaming status channel for the verification lifecycle.

<Callout kind="info">

Duplicate submissions no longer return `409 Conflict`. The API now enriches the existing row instead, and stale auto-rejected rows with the same content hash are deleted before the verification run starts.


</Callout>

<ParamField body="method" param-type="string" required="true" show-location="false">

`POST`


</ParamField>

<ParamField body="path" param-type="string" required="true" show-location="false">

`/api/agents/verify-stream`


</ParamField>

<ParamField header="Authorization" param-type="string" required="true">

Bearer JWT for the authenticated user.


</ParamField>

<ParamField body="source" param-type="string" required="false" enum="publish,bounty,requested">

Lifecycle row to update.


</ParamField>

<ParamField body="sourceId" param-type="string" required="false">

Identifier for the source row referenced by `source`.


</ParamField>

<ParamField body="platforms" param-type="string[]" required="false">

Curated platform tags associated with the agent.


</ParamField>

<ParamField body="categories" param-type="string[]" required="false">

Curated category tags associated with the agent.


</ParamField>

<ParamField body="workflowSteps" param-type="string[]" required="false">

Workflow step names used during review and classification.


</ParamField>

<ParamField body="useCases" param-type="string[]" required="false">

Use case descriptions for the agent.


</ParamField>

<ParamField body="builderQuestions" param-type="array" required="false">

Builder question and answer pairs captured for review.


</ParamField>

<ParamField body="testContext" param-type="object" required="false">

Server-side end-to-end test context, including `draftFlowId`, `answers`, `consumerInputs`, and `contentHash`.


</ParamField>

### Example request

<CodeGroup tabs="cURL,JSON response">

```bash
curl -N -X POST \
  http://localhost:3001/api/agents/verify-stream \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.example" \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -d '{
    "source": "publish",
    "sourceId": "pubreq_28c91d4f",
    "platforms": ["slack", "hubspot"],
    "categories": ["sales", "automation"],
    "workflowSteps": ["capture lead", "score lead", "route contact"],
    "useCases": ["Qualify inbound leads", "Assign owners in CRM"],
    "builderQuestions": [
      {
        "question": "What input does the agent require?",
        "answer": "Lead form payload and CRM credentials."
      }
    ],
    "testContext": {
      "draftFlowId": "dflow_9de45c2a",
      "answers": {
        "crmConnected": true
      },
      "consumerInputs": {
        "company": "Northstar Health",
        "email": "maya.rao@northstarhealth.com"
      },
      "contentHash": "sha256:61e2d9b6b6c3f8dd95f6f3c17a13a440f8a4f5b5fd5f4ae6c4b79d3a9ad30211"
    }
  }'
```

```json
{
  "event": "message",
  "data": "SSE stream opened. Expect text/event-stream frames such as status updates, progress events, and final review state."
}
```

</CodeGroup>

### Response fields

<ResponseField name="event stream" field-type="text/event-stream" required="true">

Streaming response channel for verification progress and final result events.


</ResponseField>

### POST `/api/agents/approve/{id}`

Approve a pending agent review and create or associate the published workflow. If automated checks are still running and the submission status is `checking`, the API returns `400`.

<Callout kind="info">

Earlier `409` handling deleted the review row, which caused the builder dashboard card to disappear. The API now flips the status to `approved` and sets `published_workflow_id`, so the card persists and turns green.


</Callout>

<ParamField body="method" param-type="string" required="true" show-location="false">

`POST`


</ParamField>

<ParamField body="path" param-type="string" required="true" show-location="false">

`/api/agents/approve/{id}`


</ParamField>

<ParamField path="id" param-type="string" required="true">

Review submission identifier.


</ParamField>

<ParamField header="Authorization" param-type="string" required="true">

Bearer JWT for an admin user.


</ParamField>

### Example request

<CodeGroup tabs="cURL,JSON response">

```bash
curl -X POST \
  http://localhost:3001/api/agents/approve/rev_82c4dd19 \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.example"
```

```json
{
  "approved": true,
```

### Error response
