## Overview

The AI service exposes health, chat, and agent verification endpoints. Verification routes are prefixed with `/verification` and include category generation, description generation, workflow step generation, setup field validation, and streaming agent verification.

<Callout kind="info">

Implementation details on this page were derived from code analysis of `apps/ai-service/main.py`. Direct repository file reads for code files were not available through the docs repository tool for this task.


</Callout>

</ParamField>

<ParamField body="path" param-type="string" required="true" show-location="false">

## Request details

This endpoint accepts a JSON body with workflow context used for deterministic category classification.

<ParamField body="workflow_json" param-type="object" required="true" show-location="false">

The workflow JSON to classify.


</ParamField>

<ParamField body="name" param-type="string" required="false" show-location="false">

Agent name. Defaults to `""` and improves classification accuracy when provided.


</ParamField>

<ParamField body="description" param-type="string" required="false" show-location="false">

Agent description. Defaults to `""` and improves classification accuracy when provided.


</ParamField>

<Callout kind="info">

The classifier uses an LLM with temperature `0.0` for deterministic output. It maps results into a closed set of marketplace categories and drops any off-list answers.


</Callout>

### Category taxonomy

The endpoint only returns categories from this fixed taxonomy:

- Everyday
- Customer service
- Sales
- Engineering
- Finance
- HR
- IT
- Legal
- Marketing
- Operations

<CodeGroup tabs="cURL,JSON response">

```bash
curl -X POST http://localhost:8000/verification/generate-categories \
  -H "Content-Type: application/json" \
  -d '{
    "workflow_json": {
      "nodes": [
        {
          "id": "lead_lookup",
          "type": "search_crm",
          "name": "Find account owner"
        },
        {
          "id": "draft_email",
          "type": "generate_email",
          "name": "Draft follow-up email"
        }
      ],
      "edges": [
        {
          "source": "lead_lookup",
          "target": "draft_email"
        }
      ]
    },
    "name": "Outbound sales follow-up agent",
    "description": "Looks up account ownership and drafts personalized follow-up emails for open opportunities."
  }'
```

```json
{
  "categories": ["Sales", "Operations"]
}
```

</CodeGroup>

<ResponseField name="categories" field-type="string[]" required="true">

</ResponseField>

## Implementation notes

The FastAPI file defines the application with `app = FastAPI()` and registers the `GET /health` handler directly. No response model is defined for the route, and no custom exception handling appears in the file.

The AI service now includes a verification router with endpoints for category generation, description generation, workflow step generation, fillable field detection, setup field scoring, request alignment checking, prewarming, and streaming agent verification. The verification stack is pre-warmed on startup.

## Likely error responses

The current implementation mixes direct framework responses with fail-open verification behavior.

- **`404 Not Found`** — Returned when you request a path that is not defined.
- **`404 Not Found`** — Returned when you use a path or method combination that does not match the implemented route, based on the available code analysis.
- **`200 OK` with empty `categories`** — Returned by `POST /verification/generate-categories` when classification fails or the model output cannot be mapped to the fixed taxonomy.
- **`502 Bad Gateway`** — Other verification endpoints may return this status when upstream LLM calls fail.
