## Overview

Gravity integrates with external services that power its agent marketplace, billing, workflow execution, authentication, and observability.

The core integrations are:

- **Activepieces:** Workflow execution, scheduling, and approval waitpoints
- **OAuth providers:** Third-party app connections for workflow steps, including Google, Slack, Notion, and GitHub
- **Payment providers:** Razorpay and Stripe for pay-ins, plus RazorpayX, PayPal, and Stripe Connect for payouts
- **Supabase:** PostgreSQL database hosting, authentication, and row-level security
- **AI service:** Agent verification, quality review, and AI-assisted content generation
- **Observability services:** Sentry for error tracking and PostHog for product analytics

## Activepieces integration

Activepieces is the workflow engine behind Gravity's agent marketplace. Builders create automation workflows in Activepieces, Gravity publishes those workflows as marketplace agents, and consumers run the agents through Gravity's API.

Gravity handles the integration boundary between marketplace requests and Activepieces workflow runs:

- Workflow runs execute through Activepieces. Gravity resolves connections and normalizes execution results.
- Approval waitpoints pause runs until a human approves them. Gravity retains the run handle while it polls for completion.
- Gravity probes the Activepieces version and caches the result for 10 minutes to select compatible behavior.
- Schedule piece compatibility is version-gated. Gravity skips the schedule pin on Activepieces 0.87.0 and later, but retains it for older versions.
- AI provider objects exported from Activepieces Cloud are flattened to the configured provider string.
- Email addresses used during user provisioning are trimmed and lowercased to prevent account-matching failures.
- The file proxy only forwards URLs whose host matches the configured Activepieces instance URL.

<Callout kind="info">

Activepieces maintains a separate PostgreSQL database for workflow execution state, including flows, runs, and connections. Activepieces manages this schema independently from the Gravity application database.

</Callout>

### Configuration

<ParamField body="ACTIVEPIECES_INSTANCE_URL" param-type="string" required="true" show-location="false">
The URL of the Activepieces server that Gravity uses for workflow execution and file proxy validation.
</ParamField>

<ParamField body="AP_JWT_SECRET" param-type="string" required="true" show-location="false">
The shared JWT secret used for provisioning users in Activepieces.
</ParamField>

<ParamField body="AP_POSTGRES_*" param-type="string" required="true" show-location="false">
The Activepieces PostgreSQL connection variables.
</ParamField>

<ParamField body="GRAVITY_OAUTH_STATE_SECRET" param-type="string" required="false" show-location="false">
The secret used to sign OAuth state JWTs. Gravity falls back to `AP_JWT_SECRET` when this value is not configured.
</ParamField>

## OAuth provider connections

Gravity supports OAuth connections for third-party applications used by workflow steps. Each provider requires a client ID and client secret configured through environment variables. Gravity enables a provider only when both values are present.

<Callout kind="info">

OAuth providers are configured dynamically. When both `OAUTH_PROVIDER_CLIENT_ID` and `OAUTH_PROVIDER_CLIENT_SECRET` are set for a provider, Gravity makes that provider available for workflow connections. Gravity brokers OAuth flows through its API and supports both cloud and custom OAuth completion.

</Callout>

## Payment providers

Gravity uses separate payment integrations for pay-ins and payouts. Pay-ins add credits or create subscriptions, while payouts transfer creator earnings to an external account.

### Pay-in providers

<Columns cols={2}>

<Card title="Razorpay" icon="credit-card">

Razorpay handles credit purchases and subscription checkout for users in India. Gravity verifies Razorpay webhooks with an HMAC signature.

</Card>

<Card title="Stripe" icon="credit-card">

Stripe handles credit purchases and subscription checkout for international users. Gravity uses separate webhook secrets for payments, Connect, and subscriptions.

</Card>

</Columns>

Gravity selects the pay-in provider automatically using geographic information from request headers. Configure `PAYMENTS_GEO_DEFAULT_COUNTRY` to provide the fallback country when the request does not include a country header. The default fallback is `IN`.

### Payout providers

<Columns cols={3}>

<Card title="RazorpayX" icon="upload">

RazorpayX handles bank transfers and UPI payouts for creators in India. Gravity rejects placeholder webhook secrets.

</Card>

<Card title="PayPal" icon="cloud">

PayPal handles international creator payouts and supports both sandbox and live modes.

</Card>

<Card title="Stripe Connect" icon="link">

Stripe Connect handles onboarding for international creators and processes their payouts.

</Card>

</Columns>

<Callout kind="alert">

Gravity protects payout creation with database-level advisory locks and guarded operations to prevent duplicate withdrawals. Duplicate requests return a conflict response, and requests that exceed available earnings return a structured error.

</Callout>

## Supabase

Gravity uses Supabase for PostgreSQL hosting, authentication, and row-level security. The API accesses the database through the Supabase client and the `pg` library.

### Configuration

<ParamField body="SUPABASE_URL" param-type="string" required="true" show-location="false">
The Supabase project URL.
</ParamField>

<ParamField body="SUPABASE_ANON_KEY" param-type="string" required="true" show-location="false">
The public Supabase client key.
</ParamField>

<ParamField body="SUPABASE_SERVICE_ROLE_KEY" param-type="string" required="true" show-location="false">
The administrative Supabase key. This key bypasses row-level security and must remain server-side.
</ParamField>

<ParamField body="SUPABASE_DB_URL" param-type="string" required="true" show-location="false">
The direct PostgreSQL connection URL used by migration scripts.
</ParamField>

Gravity authenticates API requests with Supabase JWT bearer tokens. Most API endpoints require a valid token, and administrative endpoints additionally require an administrator role.

## AI service integration

Gravity communicates with a Python FastAPI service over HTTP for agent verification, quality review, and AI-assisted content generation.

### Configuration

<ParamField body="AI_SERVICE_URL" param-type="string" required="false" show-location="false">
The base URL of the AI service. The default is `http://localhost:8001`.
</ParamField>

<ParamField body="AI_SERVICE_TIMEOUT_MS" param-type="integer" required="false" show-location="false">
The HTTP request timeout in milliseconds. The default is `10000`.
</ParamField>

The AI service uses OpenRouter or OpenAI for language model access, Bedrock for guardrail checks, Gemini for embeddings and search, and Redis for session caching.
