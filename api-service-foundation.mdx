## Overview

The NestJS API is the main application and domain service for the Gravity platform. It provides authentication, agent management, marketplace execution, subscription billing, creator earnings, referrals, bounties, and integration with external services. The API serves interactive Swagger documentation at `/api/docs`.

## Bootstrap

The API boots by creating the Nest application, enabling CORS, and starting the HTTP server. CORS origins, the listening port, and the AI service URL are read from environment variables.

Key bootstrap behavior:

- **CORS:** Allows configured frontend origins with credentials.
- **Port:** Listens on the configured port, which defaults to `3001`.
- **Swagger:** Serves interactive API documentation at `/api/docs`.

## Authentication

The API uses Supabase JWT for authentication. The authentication guard protects most endpoints and validates Bearer tokens issued by Supabase. Some endpoints are public, including health checks, marketplace agent details, leaderboards, chat, the app catalog, and share link resolution.

Authentication supports:

- Email and password signup and login
- One-time password verification
- Google OAuth
- Session refresh and logout
- Profile completion and onboarding

## Module structure

The API organizes functionality into domain modules:

- **Auth:** Signup, login, OTP, password reset, Google OAuth, and session management
- **Agents:** Agent creation, publishing, verification pipeline, and review workflow with builder feedback
- **Marketplace:** Agent catalog, cloning, consumer runs, scheduled execution, trigger resolution, connection discovery, output normalization, and file proxying
- **Payments:** Credits, subscriptions, entitlements, Razorpay and Stripe pay-ins, payout accounts, and withdrawals
- **Earnings:** Creator earnings balance, FX conversion, and paginated history
- **Referrals:** Share links, attribution, monthly settlement, and referral earnings
- **Bounties:** Creation, funding, submissions, review, and payouts
- **Requested agents:** Request creation and interest tracking
- **Activepieces:** Flow management, connections, OAuth, user provisioning, capability probing, and custom-piece registration
- **Apps:** Connected app catalog and connection management
- **Composio:** Tool integrations through Composio
- **Chat:** AI assistant chat API
- **Leaderboard:** Builder and workflow rankings
- **Notifications:** In-app and email notification dispatch
- **Telemetry:** Loading duration and operation metrics
- **Health:** Service health checks

## Health endpoints

The API exposes two public health endpoints.

### GET `/`

The root endpoint checks API reachability and returns the following response:

```json
{
  "status": "ok",
  "service": "api"
}
```

### GET `/health`

The health endpoint returns the service status and the current timestamp:

```json
{
  "status": "ok",
  "service": "api",
  "timestamp": "2025-01-15T12:00:00.000Z"
}
```

## Build and packaging

The API builds with TypeScript and runs with Bun. Local development uses watch mode, and production builds compile to JavaScript before starting the server.

You can containerize the service with Docker for deployment. The container builds the application and starts the production server.

## CI integration

The API workflow in GitHub Actions covers build, versioning, image publishing, and deployment. The workflow:

- Runs on pushes to the `main` and `dev` branches
- Builds the API with the monorepo's build tooling
- Versions releases from commit message conventions for major, minor, and patch changes
- Publishes container images to the GitHub Container Registry
- Creates GitHub Releases for builds from the `main` branch
