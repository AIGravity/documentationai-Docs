## Overview

The AI service is a FastAPI application that listens on port `8001`. It exposes 30 endpoints across health and chat, internal operations, requested agents, embedding and indexing, verification, agent review, and credits.

Use the service URL that matches your deployment environment. The local development URL is `http://localhost:8001`.

## Error format

FastAPI errors use a JSON object with a `detail` field.

```json
{
  "detail": "Request could not be processed"
}
```

FastAPI returns `422 Unprocessable Entity` when request validation fails. Validation errors can include additional structured details in the `detail` field.

## Health

### GET /health

Check whether the AI service is running and whether chat has access to a configured LLM API key.

<ParamField body="method" param-type="string" required="true" show-location="false">

`GET`

</ParamField>

<ParamField body="path" param-type="string" required="true" show-location="false">

`/health`

</ParamField>

<ParamField body="authentication" param-type="string" required="false" show-location="false">

This endpoint does not require authentication.

</ParamField>

<CodeGroup tabs="cURL,Python">

```bash
curl --request GET \
  --url http://localhost:8001/health
```

```python
import requests

response = requests.get("http://localhost:8001/health", timeout=10)
response.raise_for_status()
print(response.json())
```

</CodeGroup>

<ResponseField name="status" field-type="string" required="true">

Service health status. The value is `healthy` when the health handler responds successfully.

</ResponseField>

<ResponseField name="service" field-type="string" required="true">

Service identifier. The value is `Gravity AI Interaction Layer`.

</ResponseField>

<ResponseField name="version" field-type="string" required="true">

AI service version. The current value is `1.0.0`.

</ResponseField>

<ResponseField name="chat_available" field-type="boolean" required="true">

Whether the service initialized a usable LLM configuration. The value is `true` when an LLM API key is configured and `false` otherwise.

</ResponseField>

<Response tabs="200 OK" show-lines="false">

```json
{
  "status": "healthy",
  "service": "Gravity AI Interaction Layer",
  "version": "1.0.0",
  "chat_available": true
}
```

</Response>

<Callout kind="info">

`chat_available` is dynamic. A healthy response does not guarantee that chat requests are available. Check this field before presenting chat functionality as available.

</Callout>

## Chat

### POST /chat

Send a message to the AI interaction layer and receive an execution result.

<ParamField body="user_id" param-type="string" required="true">

Identifier of the user making the request.

</ParamField>

<ParamField body="session_id" param-type="string" required="true">

Identifier of the conversation or interaction session.

</ParamField>

<ParamField body="message" param-type="string" required="true">

Message to send to the AI service.

</ParamField>

<ParamField body="agent_id" param-type="string" required="false">

Optional identifier of the agent that should process the message.

</ParamField>

<ParamField body="selected_tools" param-type="array of string" required="false">

Optional list of tools selected for the interaction.

</ParamField>

<ParamField body="submit_tools" param-type="array of string" required="false">

Optional list of tools submitted with the interaction.

</ParamField>

<Request tabs="cURL">

```bash
curl --request POST \
  --url http://localhost:8001/chat \
  --header "Content-Type: application/json" \
  --data '{
    "user_id": "usr_a1b2c3d4",
    "session_id": "sess_7f8e9d0a",
    "message": "Summarize the latest workflow activity",
    "agent_id": "agent_workflow",
    "selected_tools": ["workflow_search"],
    "submit_tools": ["workflow_search"]
  }'
```

</Request>

<Response tabs="200 OK,503 Service Unavailable" show-lines="false">

```json
{
  "execution_id": "exec_84c1f7a2"
}
```

```json
{
  "detail": "Chat service unavailable — no LLM API key configured"
}
```

</Response>

<Callout kind="alert">

The service returns `503 Service Unavailable` with detail `Chat service unavailable — no LLM API key configured` when no usable LLM API key is configured.

</Callout>

### POST /verification/verify-ap-stream

This endpoint returns server-sent events with the `text/event-stream` media type.

<Request tabs="cURL">

```bash
curl --request POST \
  --url http://localhost:8001/verification/verify-ap-stream \
  --header "Accept: text/event-stream" \
  --header "Content-Type: application/json" \
  --data '{
    "agent_id": "agent_workflow",
    "request": "Create a workflow that summarizes workflow activity"
  }'
```

</Request>

<Response tabs="200 OK" show-lines="false">

```text
event: verification
data: {"status":"complete","agent_id":"agent_workflow"}

event: done
data: {}
```

</Response>

<Callout kind="info">

`/verification/verify-ap-stream` returns `text/event-stream`, not a single JSON response. Several verification endpoints fail open on AI or provider errors and return empty results instead of propagating an error response.

</Callout>

## Agent review

### POST /agent-review/analyze

Analyze an agent configuration and, when available, its step outputs.

<Expandable title="Agent review behavior">

The agent review endpoint performs one structural analysis pass and an optional output analysis pass.

- Structural analysis runs without a model.
- Output analysis runs only when `step_outputs` are present in the request.
- Provider outages do not become review findings.

</Expandable>

<Request tabs="cURL">

```bash
curl --request POST \
  --url http://localhost:8001/agent-review/analyze \
  --header "Content-Type: application/json" \
  --data '{
    "agent_id": "agent_workflow",
    "configuration": {
      "name": "Workflow activity reviewer",
      "description": "Reviews workflow activity and summarizes recent changes"
    },
    "step_outputs": [
      {
        "step": "workflow_search",
        "output": "Three workflows changed in the last seven days"
      }
    ]
  }'
```

</Request>

## Common responses

| Status | Meaning |
| --- | --- |
| `200 OK` | The request completed successfully. |
| `403 Forbidden` | The request lacks valid administrative authorization, including an invalid or missing `x-admin-token` for admin pricing. |
| `404 Not Found` | The requested route or method is not defined. |
| `422 Unprocessable Entity` | The request does not match the endpoint's FastAPI validation schema. |
| `503 Service Unavailable` | A required service dependency is unavailable, including chat without an LLM API key. |

<Callout kind="info">

AI and provider failures do not have identical behavior across endpoint groups. Chat returns `503` when no LLM API key is configured, while several verification endpoints fail open with empty results.

</Callout>
