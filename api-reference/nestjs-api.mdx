## Overview

The NestJS API is the primary backend service and listens on port `3001`. Application routes use the global `/api` prefix, while health endpoints remain available at the root.

Authentication uses Supabase bearer tokens through the `SupabaseAuthGuard`. Routes that require administrator privileges also use the `AdminGuard`. A global validation pipe enforces whitelisted properties, rejects unknown properties, and transforms request values to their declared types.

Swagger documentation is available at [`/api/docs`](/api/docs). See the [OpenAPI specification](/api-reference/openapi) for complete schemas and generated details.

<Callout kind="info">

Send bearer tokens in the `Authorization` header using the format `Bearer <token>`. Public endpoints do not require authentication.

</Callout>

<Callout kind="alert">

Credit and subscription endpoints depend on billing feature flags. When billing is disabled, plan and checkout routes may return `404 Not Found`.

</Callout>

## Health

### GET `/health`

Returns the current API health status. This public endpoint does not require authentication.

**Auth:** Public

<CodeGroup tabs="cURL,Response">

```bash
curl -i http://localhost:3001/health
```

```json
{
  "status": "ok",
  "service": "api",
  "timestamp": "2025-01-15T12:00:00.000Z"
}
```

</CodeGroup>

<ResponseField name="status" field-type="string" required="true">

Health state. The value is `ok` when the API is running.

</ResponseField>

<ResponseField name="service" field-type="string" required="true">

Service identifier. The value is `api`.

</ResponseField>

<ResponseField name="timestamp" field-type="string" required="true">

ISO 8601 timestamp for the health check response.

</ResponseField>

## Authentication

Authentication routes are available under `/api/auth`.

### POST `/api/auth/signup`

Creates a user account and returns the user profile with authentication tokens.

**Auth:** Public

#### Request body

<ParamField body="email" param-type="string" required="true">

Email address for the new account.

</ParamField>

<ParamField body="password" param-type="string" required="true">

Password for the new account.

</ParamField>

<ParamField body="userType" param-type="string" required="true">

Account user type.

</ParamField>

<ParamField body="fullName" param-type="string" required="false">

Full name associated with the account.

</ParamField>

<ParamField body="industry" param-type="string" required="false">

Industry associated with the account.

</ParamField>

<ParamField body="profession" param-type="string" required="false">

Profession associated with the account.

</ParamField>

#### Response

Returns a user object and authentication tokens.

<ResponseField name="user" field-type="object" required="true">

Created user profile.

</ResponseField>

<ResponseField name="accessToken" field-type="string" required="true">

Bearer token for authenticated API requests.

</ResponseField>

<ResponseField name="refreshToken" field-type="string" required="true">

Token used to obtain a refreshed access token.

</ResponseField>

#### Errors

- `400 Bad Request`: Request validation failed.
- `409 Conflict`: An account already exists for the email address.

<CodeGroup tabs="cURL,Response">

```bash
curl -X POST http://localhost:3001/api/auth/signup \
  -H "Content-Type: application/json" \
  -d '{

    "password": "ExamplePassword_42",
    "userType": "creator",
    "fullName": "Jane Chen",
    "industry": "Software",
    "profession": "Product designer"
  }'
```

```json
{
  "user": {
    "id": "usr_a1b2c3d4",
    "email": "jane.chen@acme.test",
    "userType": "creator",
    "fullName": "Jane Chen"
  },
  "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.example",
  "refreshToken": "refresh_example_8f3k2m1q"
```

</CodeGroup>

**Auth:** Public

#### Request body

<ParamField body="userId" param-type="string" required="true">

</ParamField>

<ParamField body="sessionId" param-type="string" required="true">

</ParamField>

<ParamField body="message" param-type="string" required="true">

</ParamField>

#### Response

Returns the AI interaction response, including generated content and session metadata when available.

<ResponseField name="response" field-type="object" required="true">

AI interaction result.

</ResponseField>

#### Errors

- `400 Bad Request`: Request fields are missing or invalid.
- `502 Bad Gateway`: AI generation or upstream processing failed.
- `503 Service Unavailable`: Chat service is unavailable because no LLM key is configured.

<CodeGroup tabs="cURL,Response">

```bash
curl -X POST http://localhost:3001/api/chat/message \
  -H "Content-Type: application/json" \
  -d '{
    "userId": "usr_a1b2c3d4",
    "sessionId": "sess_7h4k2m9p",
    "message": "Summarize the latest workflow results."
  }'
```

```json
{
  "response": {
    "message": "The latest workflow completed successfully and processed 24 records.",
    "sessionId": "sess_7h4k2m9p"
  }
}
```

</CodeGroup>

### POST `/api/marketplace/run`

Runs a published workflow with the supplied input values.

**Auth:** Public

#### Request body

<ParamField body="publishedWorkflowId" param-type="string" required="true">

Identifier of the published workflow to run.

</ParamField>

<ParamField body="input" param-type="object" required="true">

Workflow input values.

</ParamField>

<ParamField body="fieldValues" param-type="object" required="true">

Resolved values for workflow fields.

</ParamField>

<ParamField body="sessionId" param-type="string" required="false">

Session identifier to associate with the workflow run.

</ParamField>

<ParamField body="idempotencyKey" param-type="string" required="false">

Key used to prevent duplicate workflow runs.

</ParamField>

#### Response

Returns the workflow run result. The response may include connection requirements, OAuth details, or a pending run.

<ResponseField name="result" field-type="object" required="true">

Workflow execution result.

</ResponseField>

<ResponseField name="needsConnections" field-type="array" required="false">

Connections required before the workflow can run.

</ResponseField>

<ResponseField name="oauth" field-type="object" required="false">

OAuth information required to authorize a connection.

</ResponseField>

<ResponseField name="pendingRun" field-type="object" required="false">

Pending run details when execution is waiting for an external action.

</ResponseField>

#### Errors

- `400 Bad Request`: Input or field values are missing or malformed.
- `402 Payment Required`: The user does not have sufficient credits or an eligible billing state.
- `422 Unprocessable Entity`: Workflow input is incompatible with the published workflow.

<CodeGroup tabs="cURL,Response">

```bash
curl -X POST http://localhost:3001/api/marketplace/run \
  -H "Content-Type: application/json" \
  -d '{
    "publishedWorkflowId": "workflow_pub_4k8m2n6q",
    "input": {
      "topic": "Quarterly product update"
    },
    "fieldValues": {
      "audience": "Existing customers"
    },
    "sessionId": "sess_7h4k2m9p",
    "idempotencyKey": "run_20250115_product_update"
  }'
```

```json
{
  "result": {
    "status": "completed",
    "gravityRunId": "gravity_run_6d2f8a1c"
  },
  "needsConnections": [],
  "pendingRun": null
}
```

</CodeGroup>

## Common error responses

The API uses these status codes across endpoint groups.

| Status | Meaning | Common causes |
| --- | --- | --- |
| `400 Bad Request` | Request is invalid. | DTO validation failure, missing value, or malformed value. |
| `401 Unauthorized` | Authentication failed. | Missing or invalid bearer token, or invalid webhook signature. |
| `403 Forbidden` | Authenticated caller lacks permission. | Admin-only route, ownership restriction, or user-type restriction. |
| `404 Not Found` | Requested resource or feature is unavailable. | Missing resource or disabled billing feature. |
| `409 Conflict` | Request conflicts with existing data. | Duplicate signup or another resource conflict. |
| `422 Unprocessable Entity` | Request is syntactically valid but fails domain validation. | Workflow incompatibility or business-rule violation. |
| `500 Internal Server Error` | Unexpected server failure. | Unhandled server error. Response details are masked. |
| `502 Bad Gateway` | An upstream service failed. | AI generation or embedding failure. |
| `503 Service Unavailable` | A required service is unavailable. | AI chat is unavailable because no LLM key is configured. |

<Callout kind="info">

Error responses may include a message and additional validation details. Do not rely on internal error details being returned in production.

</Callout>
