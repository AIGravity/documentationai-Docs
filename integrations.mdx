## Overview

Gravity integrates with several external services to power workflow execution, authentication, billing, payouts, AI capabilities, and tool connections. This page describes each integration and what it provides from a user's perspective.

## Activepieces

Activepieces is the workflow execution engine. When you run an agent, Gravity creates or imports an Activepieces flow and executes it there.

- **Workflow execution:** Published agents run as Activepieces flows. Gravity imports workflow templates, resolves trigger pieces, and manages the flow lifecycle, including publish, activate, pause, and deactivate.
- **Connections:** You authorize external services through Activepieces connection flows. Gravity detects required connections from the workflow and guides you through OAuth or API key setup.
- **Capability probing:** Gravity probes the Activepieces instance version through its flags endpoint and caches the result for ten minutes. When the engine supports native interval scheduling in version 0.87.0 or later, Gravity uses it directly. Older versions use a compatibility pin. The same Gravity build works before and after an Activepieces upgrade without requiring a matching Gravity release. Unknown or unreachable versions conservatively retain the compatibility pin.
- **AI provider normalization:** Activepieces Cloud may export provider configuration with an account-specific config ID. Gravity strips the config ID and uses a bare provider string so the workflow can run in your workspace without exposing the exporting account's credentials.
- **File proxying:** Gravity proxies file URLs only when the URL host matches its configured Activepieces instance. Third-party URLs with similar paths remain untouched, preventing unintended cross-origin file access.
- **Custom pieces:** Gravity registers and verifies custom pieces for publish gates, runtime checkpoints, and AI integration against the target Activepieces version. Custom-piece compatibility has been verified on Activepieces 0.90.2.
- **User provisioning:** Gravity provisions Activepieces user accounts and projects, manages sessions, and repairs stale identity mappings.

<Callout kind="info">

An Activepieces upgrade does not require a matching Gravity release. Gravity detects the Activepieces version at runtime and adapts its compatibility behavior automatically.

</Callout>

## Supabase

Supabase provides authentication and platform persistence.

Gravity uses Supabase for:

- User authentication through email and password, one-time passwords, and Google OAuth
- JWT issuance and verification for API requests
- Platform data storage for identities, profiles, billing records, marketplace workflows, earnings, referrals, bounties, and review state

## Payment providers

Gravity uses multiple payment providers for pay-ins and payouts.

### Razorpay

Razorpay processes payments for users in India, including subscriptions, credit top-ups, and bounty funding. It also handles payment webhooks.

### Stripe

Stripe processes payments for users outside India, including subscriptions and credit top-ups. Stripe Connect supports creator payouts in non-India regions.

### RazorpayX

RazorpayX processes bank transfer payouts for creators in India.

### PayPal

PayPal supports creator payouts through PayPal. The current integration uses a demo-style email connection rather than full partner onboarding.

<Callout kind="info">

Checkout automatically routes to the correct provider based on your region. India-based users are routed to Razorpay. Users in other regions use Stripe when available.

</Callout>

## OpenRouter

OpenRouter provides LLM routing across supported model providers. Gravity uses it for AI-assisted features such as intent detection, agent search, agent verification, content generation, and the review pipeline.

Gravity also tracks model costs so AI usage can be correlated with billing.

## Composio

Composio provides tool integrations that agents can use. Gravity manages the connection lifecycle for Composio apps by:

- Detecting Composio apps used by a workflow
- Initiating OAuth connections and checking connection status
- Connecting, disconnecting, and listing connections

## Connection types

Gravity supports several ways to authorize services used by agents.

- **OAuth connections:** Authorize a service through its OAuth flow. Use Gravity-managed configuration or provide custom OAuth client credentials.
- **API key connections:** Add API credentials for services that authenticate with keys.
- **Activepieces connections:** Reuse existing Activepieces connections when an agent relies on services configured through Activepieces.
- **Custom OAuth credentials:** Provide your own OAuth client credentials when a service requires your own client registration.

## Troubleshooting

<ExpandableGroup>

<Expandable title="An action step cannot resolve on the current Activepieces version">

Gravity rejects unresolvable action versions before execution begins. The error identifies the affected step and app, instead of allowing the flow to proceed and fail later without a useful explanation.

Check whether the action version is supported by the Activepieces instance connected to Gravity. Update the workflow to use a supported action version, then publish the agent again.

</Expandable>

<Expandable title="A connection is required before a run can start">

Gravity detects required connections from the workflow and surfaces them before execution begins. Authorize each requested service through its OAuth flow, API key form, or existing Activepieces connection before starting the run.

If the required connection does not appear, confirm that the workflow includes the expected app and that the connection type matches the service's authentication requirements.

</Expandable>

</ExpandableGroup>
