## Current health checks at a glance

The NestJS API and FastAPI AI service expose health endpoints that return service status information. The NestJS API also exposes a root endpoint with a basic service payload.

### Current endpoints

Use these paths when you verify the services based on the current local ports:

- **NestJS API root**: `GET http://localhost:3001/`
- **NestJS API health**: `GET http://localhost:3001/health`
- **FastAPI AI service health**: `GET http://localhost:8001/health`

### Implemented response payloads

#### NestJS API root response

```json
{
  "status": "ok",
  "service": "api"
}
```

#### NestJS API health response

```json
{
  "status": "ok",
  "service": "api",
  "timestamp": "2026-09-07T12:00:00.000Z"
}
```

#### FastAPI AI service response

```json
{
  "status": "healthy",
  "service": "Gravity AI Interaction Layer",
  "version": "1.0.0",
  "chat_available": true
}
```

## Exact response payloads

These response bodies describe the fields currently returned by each service.

### NestJS API response

```json
{
  "status": "ok",
  "service": "api",
  "timestamp": "2026-09-07T12:00:00.000Z"
}
```

<ResponseField name="status" field-type="string" required="true">
Returns `ok`.
</ResponseField>

<ResponseField name="service" field-type="string" required="true">
Returns `api`.
</ResponseField>

<ResponseField name="timestamp" field-type="string" required="true">
Returns the health check time as an ISO 8601 timestamp.
</ResponseField>

### FastAPI AI service response

```json
{
  "status": "healthy",
  "service": "Gravity AI Interaction Layer",
  "version": "1.0.0",
  "chat_available": true
}
```

<ResponseField name="status" field-type="string" required="true">
Returns `healthy` when the service reports a healthy state.
</ResponseField>

<ResponseField name="service" field-type="string" required="true">
Identifies the service as `Gravity AI Interaction Layer`.
</ResponseField>

<ResponseField name="version" field-type="string" required="true">
Returns the running AI service version.
</ResponseField>

<ResponseField name="chat_available" field-type="boolean" required="true">
Indicates whether the chat and LLM service is available.
</ResponseField>

## Verify each endpoint locally

Run each request directly against the local service port. A successful check returns the response shape shown in the previous section.

<Steps>
  <Step title="Check the NestJS API health endpoint" icon="terminal">

Use the local health URL:

<CodeGroup tabs="cURL,Expected response">

```bash
curl http://localhost:3001/health
```

```json
{
  "status": "ok",
  "service": "api",
  "timestamp": "2026-09-07T12:00:00.000Z"
}
```

</CodeGroup>

Success looks like a `200` response with `status`, `service`, and an ISO 8601 `timestamp` field.

  </Step>

  <Step title="Check the FastAPI AI service health endpoint" icon="terminal">

Use the local AI service health URL:

<CodeGroup tabs="cURL,Expected response">

```bash
curl http://localhost:8001/health
```

```json
{
  "status": "healthy",
  "service": "Gravity AI Interaction Layer",
  "version": "1.0.0",
  "chat_available": true
}
```

</CodeGroup>

Success looks like a `200` response with the service status, service name, version, and `chat_available` state.

  </Step>
</Steps>

## What these checks validate

The NestJS endpoint confirms that the API is reachable and returns its current service status with the time of the check. The FastAPI endpoint reports the AI service status, running version, and whether chat functionality is available.

<Callout kind="info">

These checks do not demonstrate database connectivity, queue health, external API reachability, or broader application readiness. The AI service check does report `chat_available`, which indicates whether the chat and LLM service is available.

</Callout>

### Service-readiness notes

- **NestJS API**: Confirms that the API serves its health route and returns `status`, `service`, and `timestamp`.
- **FastAPI AI service**: Confirms that the AI service serves its health route and returns `status`, `service`, `version`, and `chat_available`.
- **Chat availability**: Use `chat_available` to distinguish general AI service reachability from chat and LLM availability.
