## Overview

This page documents the NestJS backend service routes currently implemented in the AIGravity core repository. The code analysis found a public health endpoint at `GET /health` and telemetry endpoints at `/api/telemetry/loading-durations` for loading duration tracking.

<Callout kind="info">

Implementation details on this page were derived from code analysis of the NestJS backend implementation, rather than direct file reads through the docs repository tool.


</Callout>

<Callout kind="alert">

The repository README mentions `GET /api/health`, but the code currently implements `GET /health`. No global prefix is configured, so the `/api` path is not active for the health endpoint.


</Callout>

## Telemetry endpoints

Two unauthenticated endpoints track rolling-average durations for loading phases. Anonymous visitors generate most loads, so no authentication is required.

### GET `/api/telemetry/loading-durations`

Retrieve the global rolling-average duration for each tracked loading phase.

<ParamField body="method" param-type="string" required="true" show-location="false">

`GET`


</ParamField>

<ParamField body="path" param-type="string" required="true" show-location="false">

`/api/telemetry/loading-durations`


</ParamField>

<ParamField body="auth" param-type="string" required="true" show-location="false">

No authentication required. These endpoints are intentionally unauthenticated.


</ParamField>

#### Example request

<CodeGroup tabs="cURL">

```bash
curl -i http://localhost:3001/api/telemetry/loading-durations
```

</CodeGroup>

#### Response

Returns a JSON object mapping each operation key to its rolling-average duration and sample count.

<CodeGroup tabs="JSON">

```json
{
  "durations": {
    "analyzing:submit_prompt": { "avgMs": 6000, "n": 42 },
    "connecting": { "avgMs": 2000, "n": 18 },
    "executing": { "avgMs": 20000, "n": 7 }
  }
}
```

</CodeGroup>

##### Response fields

<ResponseField name="durations" field-type="object" required="true">

A map of operation keys to their duration statistics. Each value contains `avgMs` (rolling-average duration in milliseconds) and `n` (number of samples recorded).


</ResponseField>

#### Allowed operation keys

The following operation keys are tracked:

| Key | Description |
| --- | --- |
| `analyzing:submit_prompt` | Time to process a submitted prompt |
| `analyzing:select_intent` | Time to select an automation intent |
| `analyzing:submit_tools` | Time to process selected tools |
| `connecting` | Time to set up an agent connection |
| `deploying` | Time to deploy an agent |
| `executing` | Time to execute an agent run |
| `executing:` followed by an agent identifier | Per-agent execution time for a specific agent |

### POST `/api/telemetry/loading-durations`

Record a single completed loading-phase duration into its rolling average.

<ParamField body="method" param-type="string" required="true" show-location="false">

`POST`


</ParamField>

<ParamField body="path" param-type="string" required="true" show-location="false">

`/api/telemetry/loading-durations`


</ParamField>

<ParamField body="auth" param-type="string" required="true" show-location="false">

No authentication required.


</ParamField>

#### Request body

<ParamField body="opKey" param-type="string" required="true">

The operation key identifying which loading phase was measured. Must be one of the allowed values listed above.


</ParamField>

<ParamField body="durationMs" param-type="number" required="true">

The duration of the loading phase in milliseconds. Values are clamped to the range `50` to `600000` milliseconds before being recorded.


</ParamField>

#### Example request

<CodeGroup tabs="cURL">

```bash
curl -i -X POST http://localhost:3001/api/telemetry/loading-durations \
  -H "Content-Type: application/json" \
  -d '{"opKey": "connecting", "durationMs": 1800}'
```

</CodeGroup>

#### Response

A successful request returns a `201` status with no response body.

<Callout kind="info">

The rolling average uses a capped incremental mean. For the first approximately 20 samples, the average is a true mean. After that, it transitions to a recency-weighted rolling average with an effective window of about 20 samples.


</Callout>

## Notes

The NestJS bootstrap code enables CORS for origin `http://localhost:3000` and sets `credentials` to `true`. The application listens on port `3001`, so the health endpoint is available at `http://localhost:3001/health` in the current local configuration. The application also exposes telemetry endpoints under the `/api/telemetry` path.
