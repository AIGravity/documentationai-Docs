## Overview

Gravity is a platform for building, publishing, and running AI-powered workflow agents. Builders create agents from automation workflows, submit them for review, and earn credits when consumers run their agents.

Consumers browse the marketplace, connect their accounts, and run agents on demand or on a schedule. Gravity manages billing, credits, earnings, payouts, referrals, and workflow execution across the platform.

## How agents flow through the platform

Agents move from builder creation through sandbox testing, review, marketplace publication, and consumer execution. Approved agents generate creator earnings when consumers run them.

```mermaid
graph LR
  A[Builder creates agent] --> B[Test in sandbox]
  B --> C[Submit for review]
  C --> D[Admin review]
  D --> E{Approved?}
  E -->|Yes| F[Publish to marketplace]
  E -->|No| G[Builder report + feedback]
  G --> C
  F --> H[Consumer runs agent]
  H --> I[Builder earns credits]
  I --> J[Withdraw via payout]
```

## Billing and earnings model

Gravity uses credits to connect consumer activity with agent creator earnings:

- Consumers subscribe to a plan or purchase credit packages.
- Each agent run consumes credits based on the workflow's pricing.
- Credits are split between the platform and the agent's creator.
- Creators can withdraw earnings through supported payout methods.
- Referral earnings provide additional credits based on referred users' activity.

<Callout kind="info">

Subscription billing and enforcement are controlled by database-backed feature flags. When billing is disabled, subscription endpoints return 404. When enforcement is off, runs are not blocked by entitlement checks, allowing shadow-mode operation.

</Callout>

## Workflow run states

A workflow run moves through these states:

- **Running:** The workflow is actively executing.
- **Paused:** The workflow is waiting for an external condition, such as approval, a delay, or an agent waitpoint. Paused runs are not terminal and remain in progress.
- **Succeeded:** The workflow completed successfully.
- **Failed:** The workflow stopped because of an error, timeout, or resource limit.

<Callout kind="info">

When a run is paused for approval, the workflow stays active. Builders and consumers can poll for results for up to 2 hours for builders or 24 hours for consumers. Recurring agents retain their run handle while paused, so approval-based workflows continue functioning across cycles.

</Callout>
