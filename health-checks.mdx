## Current health checks at a glance

Two services currently expose health endpoints: the NestJS API and the FastAPI AI service. Both implement `GET /health`, return JSON payloads, and support direct local verification with `curl`.

### Current endpoints

Use these paths when you verify the services based on the current code and documented local ports:

- **NestJS API**: `GET http://localhost:3001/health`
- **FastAPI AI service**: `GET http://localhost:8001/health`

The NestJS API health route is at the root `/health` path. It is separate from application routes that use the global `/api` prefix.

## Exact response payloads

The NestJS API response includes a generated timestamp. The AI service response includes service metadata, its version, and whether chat functionality is available.

### NestJS API response

```json
{"status":"ok","service":"api","timestamp":"2025-01-15T10:30:00.000Z"}
```

<ResponseField name="status" field-type="string" required="true">
Returns `ok`.
</ResponseField>

<ResponseField name="service" field-type="string" required="true">
Returns `api`.
</ResponseField>

<ResponseField name="timestamp" field-type="string" required="true">
The time when the health response was generated, formatted as an ISO 8601 timestamp.
</ResponseField>

### FastAPI AI service response

```json
{"status":"ok","service":"ai","version":"0.1.0","chat_available":true}
```

<ResponseField name="status" field-type="string" required="true">
Returns `ok`.
</ResponseField>

<ResponseField name="service" field-type="string" required="true">
Identifies the AI service.
</ResponseField>

<ResponseField name="version" field-type="string" required="true">
Reports the running AI service version.
</ResponseField>

<ResponseField name="chat_available" field-type="boolean" required="true">
Indicates whether chat functionality is available.
</ResponseField>

## Verify each endpoint locally

Run each request directly against the local service port. A successful check returns the response shape described in the previous section.

<Steps>
  <Step title="Check the NestJS API health endpoint" icon="terminal">

Use the root-level health URL:

<CodeGroup tabs="cURL,Expected response">

```bash
curl http://localhost:3001/health
```

```json
{"status":"ok","service":"api","timestamp":"2025-01-15T10:30:00.000Z"}
```

</CodeGroup>

Success looks like a `200` response with `status` set to `ok`, `service` set to `api`, and a generated `timestamp`.

  </Step>

  <Step title="Check the FastAPI AI service health endpoint" icon="terminal">

Use the AI service on port `8001`:

<CodeGroup tabs="cURL,Expected response">

```bash
curl http://localhost:8001/health
```

```json
{"status":"ok","service":"ai","version":"0.1.0","chat_available":true}
```

</CodeGroup>

Success looks like a `200` response with `status`, `service`, and `version` fields, plus a boolean `chat_available` value.

  </Step>
</Steps>

## What these checks validate

The NestJS endpoint validates that the API process is serving a reachable HTTP route and reports when it generated the response. The AI endpoint also reports service metadata and whether chat functionality is currently available.

<Callout kind="info">

The health checks do not demonstrate database connectivity, queue health, external API reachability, or general application readiness. The AI service's `chat_available` field is the only readiness signal exposed by these responses.

</Callout>

### Service-readiness notes

- **NestJS API**: Confirms that the API process is serving `GET /health`, returns `status` and `service`, and includes a response timestamp.
- **FastAPI AI service**: Confirms that the AI service process is serving `GET /health`, reports its service and version, and exposes the `chat_available` readiness signal.
- **Neither endpoint** currently exposes database, queue, model dependency, or external service health.
