## Overview

The NestJS API service exposes public health and leaderboard endpoints, plus authenticated agent endpoints for category preview, publishing, and review submission. Agent routes require JWT authentication, while leaderboard and health routes are public.

<Callout kind="info">

Implementation details on this page were derived from code analysis of `apps/api/src/main.ts`, `apps/api/src/app.module.ts`, and controller implementations in the AIGravity core repository, rather than direct file reads through the docs repository tool.


</Callout>

## POST `/api/agents/preview-categories`

Use this endpoint to get AI-generated marketplace category suggestions before publishing an agent.

<ParamField body="method" param-type="string" required="true" show-location="false">

`POST`


</ParamField>

<ParamField body="path" param-type="string" required="true" show-location="false">

`/api/agents/preview-categories`


</ParamField>

<ParamField body="auth" param-type="string" required="true" show-location="false">

JWT required.


</ParamField>

### Request body

<ParamField body="workflowJson" param-type="object" required="true" show-location="false">

The uploaded workflow JSON.


</ParamField>

<ParamField body="name" param-type="string" required="false" show-location="false">

Agent name. Providing a name improves classification accuracy.


</ParamField>

<ParamField body="description" param-type="string" required="false" show-location="false">

Agent description. Providing a description improves classification accuracy.


</ParamField>

<Callout kind="info">

The category suggester uses a fixed marketplace taxonomy: `Everyday`, `Customer service`, `Sales`, `Engineering`, `Finance`, `HR`, `IT`, `Legal`, `Marketing`, and `Operations`.


</Callout>

### Example request

<CodeGroup tabs="cURL">

```bash
curl -X POST http://localhost:3001/api/agents/preview-categories \
  -H "Authorization: Bearer sb_example_jwt_token_9xmk7q2r" \
  -H "Content-Type: application/json" \
  -d '{
    "workflowJson": {
      "nodes": [
        {
          "id": "lead-qualifier",
          "type": "agent",
          "name": "Lead qualifier"
        }
      ],
      "edges": []
    },
    "name": "Pipeline triage assistant",
    "description": "Classifies inbound leads and routes them to the right rep"
  }'
```

</CodeGroup>

## Response

A successful request returns one to three suggested categories.

<CodeGroup tabs="JSON">

```json
{
  "categories": ["Sales", "Operations"]
}
```

</CodeGroup>

### Response fields

<ResponseField name="categories" field-type="string[]" required="true">

Suggested marketplace categories. The response contains one to three values selected from the fixed taxonomy.


</ResponseField>

### Behavior

The endpoint calls the AI service to classify the workflow for marketplace discovery. If the AI call fails for any reason, the endpoint returns an empty `categories` array so category preview never blocks publishing.

## GET `/api/leaderboard/workflows`

Use this endpoint to fetch the per-workflow leaderboard ranked by quality score.

<ParamField body="method" param-type="string" required="true" show-location="false">

`GET`


</ParamField>

<ParamField body="path" param-type="string" required="true" show-location="false">

`/api/leaderboard/workflows`


</ParamField>

<ParamField body="auth" param-type="string" required="true" show-location="false">

No authentication required.


</ParamField>

### Query parameters

<ParamField query="limit" param-type="integer" required="false">

Maximum number of ranked workflows to return. Defaults to `100` and is clamped to the range `1` through `200`.


</ParamField>

### Example request

<CodeGroup tabs="cURL">

```bash
curl -i "http://localhost:3001/api/leaderboard/workflows?limit=25"
```

</CodeGroup>

## Response

A successful request returns ranked workflow entries and the total number of published workflows in the leaderboard.

<CodeGroup tabs="JSON">

```json
{
  "items": [
    {
      "workflowId": "wf_01j2v91f4mce",
      "workflowName": "Sales triage copilot",
      "builderUserId": "usr_01j2v8x73nqp",
      "builderName": "Jane Chen",
      "avatarUrl": "https://cdn.aigravity.dev/avatars/jane-chen.png",
      "score": 97.4,
      "builderWorkflows": 6
    }
  ],
  "total": 148
}
```

</CodeGroup>

### Response fields

<ResponseField name="items" field-type="array" required="true">

Ranked workflow entries. Each item includes `workflowId`, `workflowName`, `builderUserId`, `builderName`, `avatarUrl`, `score`, and `builderWorkflows`.


</ResponseField>

<ResponseField name="total" field-type="integer" required="true">

Total number of ranked workflows.


</ResponseField>

### Ranking behavior

The leaderboard sorts workflows by highest score first. If two workflows have the same score, the builder with more total published workflows ranks higher.

<Callout kind="info">

A single builder can appear multiple times because the leaderboard ranks published workflows, not unique builders.


</Callout>

</ParamField>

<ParamField body="path" param-type="string" required="true" show-location="false">

`/api/leaderboard/results`

<ParamField body="auth" param-type="string" required="true" show-location="false">

No authentication required.


</ParamField>

## Response

This endpoint returns the same response shape as `GET /api/leaderboard/workflows`.

<CodeGroup tabs="JSON">

```json
{
  "items": [
    {
      "workflowId": "wf_01j2v91f4mce",
      "workflowName": "Sales triage copilot",
      "builderUserId": "usr_01j2v8x73nqp",
      "builderName": "Jane Chen",
      "avatarUrl": "https://cdn.aigravity.dev/avatars/jane-chen.png",
      "score": 97.4,
      "builderWorkflows": 6,
      "prize": "$500"
    }
  ],
  "total": 148
}
```

</CodeGroup>

### Response fields

<ResponseField name="items" field-type="array" required="true">

Ranked workflow entries. The response shape matches `GET /api/leaderboard/workflows` and may include a `prize` field for ranked positions.


</ResponseField>

<ResponseField name="total" field-type="integer" required="true">

Total number of ranked workflows in the returned standings.


</ResponseField>

### Behavior

Before the season close date, the endpoint returns live provisional standings. After the season closes, it serves a frozen snapshot from the leaderboard results table. The freeze operation is idempotent.

## Notes

The API now uses explicit `/api` prefixes on controller routes for agent and leaderboard endpoints. Agent endpoints require JWT authentication through a Supabase auth guard, while health and leaderboard routes remain public. The NestJS bootstrap code enables CORS for origin `http://localhost:3000` and sets `credentials` to `true`. The application listens on port `3001`, so local requests use `http://localhost:3001`.
