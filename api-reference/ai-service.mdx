## Overview

This page documents the FastAPI AI service health endpoint and the agent search ranking behavior used to order matching agents during chat handoff. The service exposes `GET /health` and applies ranking logic that accounts for relevance, tool coverage, and platform or type matches when searching for agents.

## Agent search ranking

When a user describes a task in chat, the AI service searches for matching agents and ranks candidates before presenting results. Ranking uses a blend score that starts with base relevance and then applies additional weighting for tool coverage and platform or type matches.

### How agent candidates are ranked

The ranking score combines the underlying search relevance score with two additional factors that affect ordering:

<ParamField body="tool coverage" param-type="number" required="true" show-location="false">

The fraction of an agent's required tools that the user already has connected. Agents where the user has all required integrations rank higher than agents that would require new connections. This factor is weighted by `SEARCH_TOOL_WEIGHT`, which defaults to `0.20`.


</ParamField>

<ParamField body="platform and type match" param-type="score adjustment" required="true" show-location="false">

Bonuses applied when an agent matches the user's relevant platforms or agent types.


</ParamField>

### Soft filtering by tools

When the user has selected preferred tools, the service splits candidates into two groups before final result assembly:

<ParamField body="fits" param-type="group" required="true" show-location="false">

Agents that use at least one of the user's selected tools, or agents that declare no tool requirements. These candidates fill result slots first.


</ParamField>

<ParamField body="misfits" param-type="group" required="true" show-location="false">

Agents that declare tool requirements but none of those requirements match the user's selected tools. These candidates only backfill remaining slots when needed.


</ParamField>

This soft filtering keeps results aligned with the user's preferences without producing empty result sets when tool overlap is limited.

### Handoff turn behavior

The service now runs agent search on the handoff turn itself, before asking the user about preferred tools.

- If matching agents are found, the service asks the tools question and then re-ranks results using the user's tool selections.
- If no matching agents are found, the service skips the tools question and moves directly to the no-agent or bounty path.

<Callout kind="info">

This behavior prevents unnecessary questions when no agents match the user's task description.


</Callout>
