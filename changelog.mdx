## Overview

This changelog tracks notable user-facing changes to the Gravity platform. Each entry describes what changed and how it affects builders, consumers, or administrators.

<Update date="2026-09-22">

#### Marketplace run behavior

- Paused runs are now treated as in-progress, not terminal failures. Runs paused for approval, delay, or agent waitpoints retain their run handle and stay alive for extended polling windows: 2 hours for builders and 24 hours for consumers.
- Paused runs now include a `kind` field with one of `approval`, `delay`, `agent`, or `unknown`, so consumers can distinguish human-approval waitpoints from other pause reasons.
- `QUEUED` status from the workflow engine is now treated as `running`.
- Memory limit, log size, and quota exceeded conditions are now reported as `failed` with the provider's failure message preserved.
- Timeout results retain failed-step details.
- Unsupported action-piece versions now produce a readable `422` response that names the affected step, application, action, and version gap. Builder paths receive detailed error messages, while consumer paths receive generic copy.
- Empty Activepieces options responses now become readable errors instead of silent failures.
- Dynamic option lookup is now restricted to dynamic dropdown fields.
- Recurring agents retain their active run handle when a run is paused, and polling cadence remains slow while paused even after transient errors.

#### Agent review pipeline

- New endpoint: `POST /api/agents/review-submissions/mine/:id/feedback`. Builders can submit thumbs-up or thumbs-down feedback with optional notes on individual review findings.
- New endpoint: `POST /api/agents/admin/pending-reviews/:id/re-review`. Admins can trigger an asynchronous re-review of a previously reviewed submission.
- Sending a builder report now also rejects the submission. The report send endpoint accepts `keepIds`, `edits`, and `reason` for admin corrections.
- Admin test runs now use a shared review workspace rather than the admin's own project.
- Review results can include evidence-axis scores, penalty-by-severity breakdowns, and measured case counts.

#### Subscriptions and billing

- New subscription endpoints cover the plans catalog, current subscription, entitlement, history, checkout, cancellation, and free-plan activation.
- Checkout selects Razorpay for users in India and Stripe for international users based on geographic detection.
- New subscription webhook endpoints:
  - `POST /api/subscriptions/webhook/razorpay`
  - `POST /api/subscriptions/webhook/stripe`
- Two database-backed feature flags control billing: `subscription_billing_enabled` and `subscription_enforcement_enabled`. Both default to off and fail safely.

#### Credits, earnings, and payouts

- New earnings endpoint: `GET /api/earnings/balance`. The endpoint returns lifetime, withdrawn, and withdrawable balances.
- Payout balance checks now include pending, processing, and paid payouts to prevent double withdrawal.
- Duplicate payout requests return a conflict response.
- Insufficient earnings return a structured error.
- Payout balance checks use database-level advisory locks for concurrency safety.

#### Referrals

- New referral endpoints provide an earnings summary, share-link creation, public share-link resolution, and referral attribution.
- Referral earnings are settled monthly based on referred users' activity, with configurable rates stored in the database.

#### Activepieces integration improvements

- AI provider objects exported from Activepieces Cloud are now flattened to the configured provider string, fixing first-call failures on AI steps.
- The file proxy now only proxies URLs whose host matches the configured Activepieces instance URL. Third-party URLs pass through unchanged.
- Email lookups during Activepieces user provisioning are now normalized to lowercase and trimmed, preventing mixed-case or whitespace accounts from getting stuck.
- Schedule piece compatibility is now capability-gated. The schedule pin is skipped on Activepieces 0.87.0 and later, but retained on older versions.
- The Activepieces version is probed and cached for 10 minutes to determine which compatibility shims to apply.

#### Removed

- The legacy `/api/n8n-workflow/*` endpoints have been removed. They are not maintained as aliases. Use `/api/marketplace/*` endpoints for all workflow operations.

</Update>

## How to read this changelog

Entries are listed newest first. Each entry groups changes by functional area. Items marked as new endpoints or removed features are breaking changes for integrations that depend on the old behavior.
