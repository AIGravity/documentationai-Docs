## Bounties endpoints

Create and preview bounties from chat sessions, submit workflow solutions, manage the submission lifecycle, and process Razorpay payments. All Bounties API endpoints require a Bearer JWT in the `Authorization` header.

### POST `/api/bounties`

Create a bounty from a chat session.

If a bounty already exists for the same chat session with status `open` or `pending_payment`, this endpoint returns the existing bounty instead of creating a new one.

<ParamField body="method" param-type="string" required="true" show-location="false">

`POST`



</ParamField>

<ParamField body="sessionId" param-type="string" required="true">

Chat session ID.



</ParamField>

<ParamField body="title" param-type="string" required="false">

Bounty title.



</ParamField>

<ParamField body="summary" param-type="string" required="false">

User-edited bounty summary.



</ParamField>

<ParamField body="answers" param-type="object" required="false">

Structured question-and-answer payload used to generate the bounty.



</ParamField>

<ParamField body="answers.trigger" param-type="string" required="false">

Trigger condition or event.



</ParamField>

<ParamField body="answers.apps" param-type="string[]" required="false">

Apps or platforms involved in the workflow.



</ParamField>

<ParamField body="answers.output" param-type="string" required="false">

Expected output or outcome.



</ParamField>

<ParamField body="amount" param-type="number" required="false">

Payment amount for the bounty.



</ParamField>

<ParamField body="currency" param-type="string" required="false">

Currency code for the bounty payment.



</ParamField>

<Callout kind="info">

When `paymentRequired` is `true`, the bounty stays hidden from listings until you fund it through Razorpay. The initial status is `pending_payment` when payment is required, otherwise `open`.



</Callout>

### Example request

<CodeGroup tabs="cURL,JSON response">

```bash
curl -X POST http://localhost:3001/api/bounties \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.example" \
  -H "Content-Type: application/json" \
  -d '{
    "sessionId": "ses_9f3d2c11",
    "title": "Build a Slack triage workflow",
    "summary": "Route new support tickets from Slack into a review queue with labels.",
    "answers": {
      "trigger": "New message posted in the support-triage Slack channel",
      "apps": ["Slack", "Notion"],
      "output": "Create a triaged task in Notion with priority and owner"
    },
    "amount": 2500,
    "currency": "INR"
  }'
```

```json
{
  "id": "bty_8k2m4p1q",
  "title": "Build a Slack triage workflow",
  "summary": "Route new support tickets from Slack into a review queue with labels.",
  "expiresAt": "2026-08-15T18:30:00.000Z",
  "paymentRequired": true,
  "amount": 2500,
  "currency": "INR"
}
```

</CodeGroup>

### POST `/api/bounties/{bountyId}/submit`

Submit a workflow solution to a bounty.

<ParamField body="method" param-type="string" required="true" show-location="false">

`POST`



</ParamField>

<ParamField path="bountyId" param-type="string" required="true">

Bounty identifier.



</ParamField>

<ParamField body="workflowJson" param-type="object" required="true">

Workflow definition JSON for the submission.



</ParamField>

<ParamField body="builderQuestions" param-type="array" required="false">

Builder question-and-answer pairs associated with the submission.



</ParamField>

<Callout kind="info">

The workflow JSON must include a Publish Gate step. The `assertHasPublishGate` check runs before any save and returns `400` if the step is missing.



</Callout>

<Callout kind="alert">

If the workflow does not contain a Publish Gate step, the API returns a `400` response with the message `Workflow must include a Publish Gate step.`



</Callout>

### Example request

<CodeGroup tabs="cURL,JSON response">

```bash
curl -X POST http://localhost:3001/api/bounties/bty_8k2m4p1q/submit \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.example" \
  -H "Content-Type: application/json" \
  -d '{
    "workflowJson": {
      "name": "Slack triage workflow",
      "steps": [
        {
          "id": "step_trigger",
          "type": "slack.new_message",
          "name": "Watch support-triage"
        },
        {
          "id": "step_classify",
          "type": "ai.classify",
          "name": "Classify urgency"
        },
        {
          "id": "step_publish_gate",
          "type": "publish_gate",
          "name": "Publish Gate"
        }
      ]
    },
    "builderQuestions": [
      {
        "question": "What fields should the Notion item include?",
        "answer": "Priority, owner, source channel, and a short summary."
      }
    ]
  }'
```

```json
{
  "id": "sub_5x1q7d9m",
  "bountyId": "bty_8k2m4p1q",
  "status": "submitted"
}
```

</CodeGroup>

<ResponseField name="id" field-type="string" required="true">

Unique submission identifier.


</ResponseField>

<ResponseField name="bountyId" field-type="string" required="true">

Identifier of the bounty the submission belongs to.

<ResponseField name="status" field-type="string" required="true">
