## Overview

This changelog tracks notable API and documentation updates for the AIGravity core platform.

## Release history

1. **Bounty funding with Razorpay pay-to-post**
   - **API**
     - New endpoint `POST /api/bounties/{id}/pay/order` creates a Razorpay order to fund a bounty in `pending_payment` status. Returns Razorpay Checkout parameters including order ID, key ID, amount in minor units, and currency.
     - New endpoint `POST /api/bounties/{id}/pay/verify` verifies the HMAC-SHA256 Checkout signature, marks the order as paid, and transitions the bounty from `pending_payment` to `open`. Returns `PAID` or `ALREADY_PAID` for idempotent re-calls.
     - `POST /api/bounties` response now includes `paymentRequired` (boolean), `amount` (number), and `currency` (string). When `paymentRequired` is true, the bounty starts in `pending_payment` status and the client must complete the pay-to-post flow before it goes live.
     - `GET /api/bounties/by-session/{sessionId}` response expanded with `bountyId`, `title`, `amount`, `currency`, and `status` fields for dashboard state reconstruction after session reload.
     - `POST /api/webhooks/razorpay` now routes bounty orders before credit orders. For `payment.captured` and `order.paid` events, the handler checks `bounty_orders` first, then falls back to `credit_orders`.
   - **Data models**
     - New `bounty_orders` table with UUID primary key, foreign keys to `bounties` and `auth.users`, CHECK constraints on `amount_minor` and `status`, and a UNIQUE constraint on `razorpay_order_id` for idempotency.
     - New columns on `bounties` table: `payment_status` (default `unpaid`, backfilled to `paid` for existing bounties) and `funded_at` (TIMESTAMPTZ).
     - New `VerifyBountyOrderDto` class-validator DTO with three required string fields: `razorpayOrderId`, `razorpayPaymentId`, `razorpaySignature`.
     - Migration `017_bounty_orders.sql` creates the table, adds columns, backfills existing data, and creates three indexes.
   - **Docs**
     - OpenAPI specification updated to version 1.1.0 with bounty and payment tags, Bearer auth scheme, and schemas for all new and modified endpoints.
     - NestJS API reference page now documents all bounty endpoints with request/response examples, parameter descriptions, and error codes.
     - Data Models Reference page updated with bounty_orders table schema, bounties table additions, DTO documentation, and migration details.
