## Overview

Use this reference to authenticate requests, check service availability, interpret errors, and find the controller responsible for each API area. The API runs on port `3001` in development.

Controllers define their own `api/...` prefixes, so the application does not add a global prefix. For example, authentication routes use `/api/auth`, while the health routes are available at `/` and `/health`.

The API applies these settings to every request:

</ParamField>

</ParamField>

<ParamField body="interceptor" param-type="string" required="true" show-location="false">

</ParamField>

<ParamField body="cors" param-type="object" required="true" show-location="false">

</ParamField>

<ParamField body="jsonBodyLimit" param-type="string" required="true" show-location="false">

</ParamField>

<ParamField body="urlEncodedBodyLimit" param-type="string" required="true" show-location="false">

</ParamField>

<ParamField body="rawRequestBodies" param-type="boolean" required="true" show-location="false">

</ParamField>

## Authentication

Protected controllers use `SupabaseAuthGuard` to validate a Supabase JWT. Send the token in the `Authorization` header using the bearer format.

```http
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
```

Routes marked with `@Public()` bypass the authentication guard. Admin routes use both `SupabaseAuthGuard` and `AdminGuard`.

<Callout kind="alert">

A valid Supabase JWT does not grant administrator access. Routes under admin controllers also require the authenticated user to pass `AdminGuard`.

</Callout>

### Authenticated user

After successful authentication, handlers receive an `AuthenticatedUser` object with this shape:

```typescript
{
  id: string
  email: string
  userType?: string
  role?: string
  userMetadata?: Record<string, unknown>
}
```

The optional `userType` and `role` values determine access to user-type-specific and administrator routes.

## Error responses

`HttpExceptionFilter` converts NestJS exceptions into a consistent JSON structure. The `requestId` field appears when the request includes an `x-request-id` value.

```json
{
  "statusCode": 400,
  "error": "BadRequestException",
  "message": "Validation failed",
  "path": "/api/auth/signup",
  "timestamp": "2026-09-07T12:00:00.000Z",
  "requestId": "req_7f3a91c2"
}
```

<ResponseField name="statusCode" field-type="integer" required="true">

HTTP status code for the error.

</ResponseField>

<ResponseField name="error" field-type="string" required="true">

Exception name, or `InternalError` for an unexpected server error.

</ResponseField>

<ResponseField name="message" field-type="string" required="true">

User-facing error message. Validation errors may contain details about invalid fields.

</ResponseField>

<ResponseField name="path" field-type="string" required="true">

Request path that produced the error.

</ResponseField>

<ResponseField name="timestamp" field-type="string" required="true">

UTC timestamp in ISO 8601 format.

</ResponseField>

<ResponseField name="requestId" field-type="string" required="false">

Request correlation identifier from the `x-request-id` header, when provided.

</ResponseField>

For unexpected 500 errors, the API returns `500` with `InternalError` and the generic message `Internal server error`. User-facing 5xx messages may pass through when an endpoint explicitly uses a safe internal server error.

## Authentication endpoints

Authentication routes use the `/api/auth` prefix. Public routes do not require a Supabase JWT. Protected routes require an `Authorization: Bearer` header.

### Check whether an email exists

#### GET `/api/auth/check-email`

Checks whether an email address is registered.

<ParamField query="email" param-type="string" required="true">

Email address to check.

</ParamField>

<CodeGroup tabs="cURL">

```bash

  --data-urlencode "email=jane.chen@acme.co"
```

</CodeGroup>

<Response tabs="200">

```json
{
  "exists": true
}
```

</Response>

<ResponseField name="exists" field-type="boolean" required="true">

Whether the email address is registered.

</ResponseField>

### Sign up

#### POST `/api/auth/signup`

Creates a creator or business account and returns the resulting user and session.

<ParamField body="email" param-type="string" required="true">

Email address for the new account.

</ParamField>

<ParamField body="password" param-type="string" required="true">

Password for the new account.

</ParamField>

<ParamField body="userType" param-type="string" required="true" enum="creator,business">

Account type.

</ParamField>

<CodeGroup tabs="cURL">

```bash
curl -X POST http://localhost:3001/api/auth/signup \
  -H "Content-Type: application/json" \
  -d '{
    "email": "jane.chen@acme.co",
    "password": "S3cureExamplePassword!",
    "userType": "creator"
  }'
```

</CodeGroup>

<Response tabs="201">

```json
{
  "user": {
    "id": "usr_a1b2c3d4",
    "email": "jane.chen@acme.co"
  },
  "session": {
    "access_token": "eyJhbGciOiJIUzI1NiIs...",
    "refresh_token": "refresh_example_7f3a91c2"
  }
}
```

</Response>

<ResponseField name="user" field-type="object" required="true">

Newly created user profile.

</ResponseField>

<ResponseField name="session" field-type="object" required="true">

Session containing access and refresh tokens.

</ResponseField>

A malformed request returns `400`. An email that is already registered returns `409`.

### Google authentication

Google authentication uses three public routes:

- `GET /api/auth/google/url`: accepts the `userType` query parameter and returns `{ "url": "..." }`. Invalid user types return `400`.
- `POST /api/auth/google/callback`: accepts `code` and `userType`, then returns a user session. Authentication failures return `401`.
- `POST /api/auth/google/id-token`: accepts `idToken` and `userType`, then returns a session. Invalid tokens return `401`.

<ParamField query="userType" param-type="string" required="true">

User type for `GET /api/auth/google/url`.

</ParamField>

<ParamField body="code" param-type="string" required="true">

Authorization code returned by Google for `POST /api/auth/google/callback`.

</ParamField>

<ParamField body="idToken" param-type="string" required="true">

Google ID token for `POST /api/auth/google/id-token`.

</ParamField>

<ParamField body="userType" param-type="string" required="true">

User type associated with the Google authentication request.

</ParamField>

<CodeGroup tabs="cURL">

```bash
curl -G http://localhost:3001/api/auth/google/url \
  --data-urlencode "userType=creator"

curl -X POST http://localhost:3001/api/auth/google/callback \
  -H "Content-Type: application/json" \
  -d '{
    "code": "google_auth_code_example_91c2",
    "userType": "creator"
  }'

curl -X POST http://localhost:3001/api/auth/google/id-token \
  -H "Content-Type: application/json" \
  -d '{
    "idToken": "google_id_token_example_7f3a",
    "userType": "creator"
  }'
```

</CodeGroup>

### Other authentication routes

The authentication controller also provides these routes:

| Method | Path | Auth | Purpose |
|---|---|---|---|
| POST | `/api/auth/admin/login` | Public | Authenticate an administrator with login credentials. Invalid or non-admin credentials return `401`. |
| POST | `/api/auth/forgot-password` | Public | Start password recovery with a generic success response that does not reveal whether the email exists. |
| POST | `/api/auth/complete-profile` | JWT | Complete the profile with `fullName`, and optionally `industry` and `profession`. |
| POST | `/api/auth/update-password` | JWT | Update the authenticated user's password using the `password` body field. |
| POST | `/api/auth/google/sync` | JWT | Synchronize a Google profile using `userType` and an optional `referralCode`. |
| POST | `/api/auth/logout` | JWT | Log out the authenticated user. |
| GET | `/api/auth/me/creator` | JWT | Return the current creator profile. A wrong user type returns `403`. |
| GET | `/api/auth/me/business` | JWT | Return the current business profile. A wrong user type returns `403`. |

## Endpoint summary

The API groups related operations by controller. Authentication requirements describe the default route behavior; individual routes may be public within an authenticated controller.

| Controller | Prefix | Auth | Description |
|---|---|---|---|
| Health | `/` | None | Service health and root status |
| Auth | `/api/auth` | Mixed, public and JWT | Authentication, OTP, OAuth, session management |
| Agents | `/api/agents` | JWT | Agent publishing, review, admin pending reviews, pricing |
| Marketplace | `/api/marketplace` | JWT, some public | Workflow catalog, publishing, connections, OAuth, running workflows, builder test, file proxy |
| Apps | `/api/apps` | JWT, catalog public | App catalog, connections, pending apps |
| ActivePieces | `/api/activepieces` | JWT | ActivePieces session management |
| Builder | `/api/builder` | JWT | Flow management and publishing |
| Builder Connections | `/api/builder/connections` | JWT | Template introspection and connection management |
| Chat | `/api/chat` | None | Chat sessions, messages, and flow state |
| Automations | `/api/automations` | JWT | Automation CRUD, tool reconnection, and runs |
| Bounties | `/api/bounties` | JWT | Bounty creation, payments, submissions, and awards |
| Requested Agents | `/api/requested-agents` | JWT | Requested-agent CRUD and interest tracking |
| Credits | `/api/credits` | JWT | Credit packages, balances, orders, and verification |
| Payouts | `/api/payouts` | JWT | Self-service and admin payouts, FX rates, and synchronization |
| Payout Accounts | `/api/payout-accounts` | JWT | Bank, PayPal, and Stripe account management |

</Callout>
