## Overview

This page documents the public endpoints exposed by the NestJS backend service. All endpoints except `/health` require a Supabase JWT bearer token passed in the `Authorization` header.

## Endpoints

### GET `/health`

Checks whether the NestJS backend is running and responding. No parameters, no authentication, and no request body.

<CodeGroup tabs="cURL">

```bash
curl -i http://localhost:3001/health
```

</CodeGroup>

<CodeGroup tabs="JSON">

```json
{
  "status": "ok",
  "service": "api"
}
```

</CodeGroup>

#### Response fields

<ResponseField name="status" field-type="string" required="true">

Health state returned by the endpoint. The handler returns `ok`.


</ResponseField>

<ResponseField name="service" field-type="string" required="true">

Service identifier returned by the endpoint. The handler returns `api`.


</ResponseField>

### POST `/api/credits/orders`

Creates a Razorpay credit order for the authenticated user from a predefined credit package.

<Callout kind="info">

EUR and GBP currencies were added in this release. Previously, only INR and USD were accepted, and requests with EUR or GBP returned a `400` error.


</Callout>

#### Authentication

Pass a Supabase JWT bearer token in the `Authorization` header.

#### Request body

<ParamField body="packageId" param-type="string" required="true">

Identifier of the credit package to purchase, for example `pkg_starter`.


</ParamField>

<ParamField body="currency" param-type="string" required="true" enum="INR,USD,EUR,GBP">

Currency for the order. INR and USD use package prices directly. EUR and GBP amounts are derived from the USD package price at a live FX rate.


</ParamField>

<CodeGroup tabs="JSON">

```json
{
  "packageId": "pkg_starter",
  "currency": "USD"
}
```

</CodeGroup>

#### Response fields

<ResponseField name="orderId" field-type="string" required="true">

Internal credit order identifier as a UUID.


</ResponseField>

<ResponseField name="razorpayOrderId" field-type="string" required="true">

Razorpay order ID to pass to the Checkout SDK.


</ResponseField>

<ResponseField name="razorpayKeyId" field-type="string" required="true">

Public Razorpay key ID. Safe to send to the browser.


</ResponseField>

<ResponseField name="amountMinor" field-type="integer" required="true">

Order amount in the smallest currency unit: paise for INR, cents for USD, EUR, and GBP.


</ResponseField>

<ResponseField name="currency" field-type="string" required="true">

Currency of the order: `INR`, `USD`, `EUR`, or `GBP`.


</ResponseField>

<ResponseField name="credits" field-type="integer" required="true">

Number of credits the user will receive after successful payment.


</ResponseField>

<ResponseField name="packageName" field-type="string" required="true">

Human-readable package name.


</ResponseField>

<CodeGroup tabs="JSON">

```json
{
  "orderId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "razorpayOrderId": "order_Nk7t2XyZ123abc",
  "razorpayKeyId": "rzp_test_ABCDEF12345",
  "amountMinor": 50000,
  "currency": "USD",
  "credits": 5000,
  "packageName": "Starter Pack"
}
```

</CodeGroup>

#### Error responses

- **`400 Bad Request`** — Validation failed or the requested currency is not supported.
- **`401 Unauthorized`** — Missing, expired, or invalid bearer token.

### GET `/api/builders/me`

Returns the authenticated user's builder profile, including currency preference and lifetime earnings.

<Callout kind="info">

This endpoint now self-heals: if the user does not have a `builders` table row, it attempts to create one with default values before returning. Creator-typed accounts that have earned credits now receive a `200` response with default values instead of a `404`. A `404` is returned only when no profile record exists at all.


</Callout>

#### Authentication

Pass a Supabase JWT bearer token in the `Authorization` header. This endpoint accepts no request body, path parameters, or query parameters.

#### Response fields

<ResponseField name="userId" field-type="string" required="true">

The builder's user ID as a UUID.


</ResponseField>

<ResponseField name="currency" field-type="string" required="true">

The builder's preferred display currency: `INR`, `USD`, `EUR`, or `GBP`.


</ResponseField>

<ResponseField name="totalEarnings" field-type="number" required="true">

Legacy earnings column. This value is always `0`. Use `lifetimeEarningsUsd` instead.


</ResponseField>

<ResponseField name="lifetimeEarningsCredits" field-type="number" required="true">

Total credits earned from agent runs, aggregated from the creator earnings ledger.


</ResponseField>

<ResponseField name="lifetimeEarningsUsd" field-type="number" required="true">

Lifetime earnings in USD, calculated as `lifetimeEarningsCredits / 100` where `1` credit equals `$0.01`.


</ResponseField>

<ResponseField name="createdAt" field-type="string" required="true">

ISO 8601 timestamp for when the profile was created.


</ResponseField>

<ResponseField name="updatedAt" field-type="string" required="true">

ISO 8601 timestamp for when the profile was last updated.


</ResponseField>

<CodeGroup tabs="JSON">

```json
{
  "userId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "currency": "USD",
  "totalEarnings": 0,
  "lifetimeEarningsCredits": 12500,
  "lifetimeEarningsUsd": 125.0,
  "createdAt": "2025-06-01T10:00:00Z",
  "updatedAt": "2025-07-04T12:30:00Z"
}
```

</CodeGroup>

#### Error responses

- **`401 Unauthorized`** — Missing, expired, or invalid bearer token.
- **`404 Not Found`** — No profile record found.

### POST `/api/marketplace/builder-fields`

Returns the consumer intake fields configured by the agent builder for a published marketplace workflow.

<Callout kind="info">

The response now includes a separate `description` field on each field object for builder-written helper text. The `question` field is derived from the builder's label and no longer contains the description text. Previously, the `question` field could contain the description instead of the label. `question` and `description` are now always distinct.


</Callout>

#### Authentication

Pass a Supabase JWT bearer token in the `Authorization` header.

#### Request body

<ParamField body="agentId" param-type="string" required="false">

The published workflow UUID to retrieve builder fields for. If omitted, the endpoint returns an empty `fields` array.


</ParamField>

#### Response fields

<ResponseField name="fields" field-type="array" required="true">

Array of builder-configured consumer input fields.


</ResponseField>

<ResponseField name="source" field-type="string" required="true">

How fields were resolved. Values: `no-agent-id`, `no-ap-row`, or `ap-consumer-inputs`.


</ResponseField>

#### Field object properties

<ResponseField name="question" field-type="string" required="true">

Primary prompt shown to the consumer. Derived from the builder's label.


</ResponseField>

<ResponseField name="description" field-type="string" required="false">

Builder-written helper text shown beneath the question as a secondary caption.


</ResponseField>

<ResponseField name="fieldType" field-type="string" required="false">

Input type. Supported values include `text`, `multiline`, `secret`, `number`, `checkbox`, `date`, `dropdown`, `static-dropdown`, `static-multi-dropdown`, `dynamic-dropdown`, `dynamic-multi-dropdown`, `dynamic-cascade`, `markdown`, `array`, and `file`.


</ResponseField>

<ResponseField name="required" field-type="boolean" required="false">

Whether the consumer must provide a value.


</ResponseField>

<ResponseField name="canonicalName" field-type="string" required="false">

The ActivePieces canonical webhook body key.


</ResponseField>

<ResponseField name="engine" field-type="string" required="false">

Workflow engine. For ActivePieces agents, this value is always `ap`.


</ResponseField>

<ResponseField name="reason" field-type="string" required="true">

Categorization of the field. For ActivePieces inputs, this value is always `consumer-input`.


</ResponseField>

<CodeGroup tabs="JSON">

```json
{
  "fields": [
    {
      "id": "wf-abc123::user_query",
      "question": "What would you like to analyze?",
      "description": "Provide a URL or paste text for the agent to process.",
      "nodeName": "",
      "paramPath": "step_1.input.query",
      "label": "What would you like to analyze?",
      "currentValue": "",
      "reason": "consumer-input",
      "engine": "ap",
      "canonicalName": "user_query",
      "fieldType": "multiline",
      "required": true
    }
  ],
  "source": "ap-consumer-inputs"
}
```

</CodeGroup>

#### Error responses

- **`400 Bad Request`** — Request body is invalid.
- **`401 Unauthorized`** — Missing, expired, or invalid bearer token.

## Notes

The NestJS bootstrap code enables CORS for origin `http://localhost:3000` and sets `credentials` to `true`. The application listens on port `3001`, and all authenticated endpoints on this page use the same base URL and port.
