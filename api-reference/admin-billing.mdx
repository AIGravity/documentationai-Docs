## Query billing metrics and user-level billing history

Use these admin-only endpoints to inspect platform-wide billing performance, rank top workflows and creators, analyze leakage signals, and drill into a single user's billing activity. You can also exclude accounts flagged as test users so revenue and usage figures reflect customer activity only.

## Authentication

Every endpoint under `/api/admin/billing` requires a valid JWT and an admin role. The API accepts authenticated requests only after JWT validation succeeds, then checks `app_metadata.role` for the `admin` value.

<Callout kind="alert">

Missing or invalid JWTs return `401 Unauthorized`. Authenticated users without the admin role return `403 Forbidden`.


</Callout>

### Base URL

Use `http://localhost:3000` in local development, or your production API base URL in deployed environments.

### Authorization header

<CodeGroup tabs="cURL,JSON response">

```bash
curl -X GET "http://localhost:3000/api/admin/billing/overview" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.example-admin-token" \
  -H "Accept: application/json"
```

```json
{
  "statusCode": 401,
  "message": "Unauthorized"
}
```

</CodeGroup>

<Callout kind="info">

The `excludeTest` query parameter is available on the overview, top-workflows, top-creators, and leakage endpoints. When set to `1` or `true`, users flagged with `is_test_account` on the `profiles` table are excluded from all metrics. Use this to view customer revenue without internal test activity.


</Callout>

<Callout kind="info">

When `approx` is `true` in a response, an all-time scan exceeded the 50,000-row cap. All figures in that response are a floor, not an exact count.


</Callout>

## GET `/api/admin/billing/overview`

Retrieve the headline billing and revenue metrics used by the admin billing dashboard. This endpoint also returns cash collection, creator liability, failed charge counts, and gross margin.

### Query parameters

<ParamField query="excludeTest" param-type="string" required="false">

Pass `1` or `true` to exclude users flagged as `is_test_account` from all metrics. Omit the parameter to include all users.


</ParamField>

<CodeGroup tabs="cURL,JSON response">

```bash
curl -X GET "http://localhost:3000/api/admin/billing/overview?excludeTest=true" \
```

### Response fields

<ResponseField name="generatedAt" field-type="string" required="true">

ISO 8601 timestamp for when the overview metrics were computed.


</ResponseField>

<ResponseField name="totalRevenue" field-type="number" required="true">

All-time sum of credits charged where charge status is `CHARGED`.


</ResponseField>

<ResponseField name="revenueToday" field-type="object" required="true">

Credits charged during the current IST calendar day. The object contains `value`, `prev`, and `changePct`. `changePct` is `null` when the previous period value is `0`.


</ResponseField>

<ResponseField name="revenueWeek" field-type="object" required="true">

Credits charged during the last 7 days. The object contains `value`, `prev`, and `changePct`.


</ResponseField>

<ResponseField name="activeWorkflowCopies" field-type="number" required="true">

Count of active subscription workflow copies.


</ResponseField>

<ResponseField name="scheduledRunsProcessed" field-type="number" required="true">

Count of cron charges with status `CHARGED`.


</ResponseField>

<ResponseField name="creatorEarnings" field-type="number" required="true">

All-time sum of creator earnings in credits.


</ResponseField>

<ResponseField name="failedCharges" field-type="number" required="true">

Total failed charges across insufficient balance and run failure outcomes.


</ResponseField>

<ResponseField name="failedBreakdown" field-type="object" required="true">

Breakdown of failed charges by type. The object contains `insufficientBalance` and `runFailed`.


</ResponseField>

<ResponseField name="llmCostCredits" field-type="number" required="true">

All-time raw 1x LLM cost across `workflow_llm_calls` and `llm_call_logs`, measured in credits.


</ResponseField>

<ResponseField name="marginPct" field-type="number | null" required="true">

Gross margin percentage. Returns `null` when `totalRevenue` is `0`.


</ResponseField>

<ResponseField name="moneyIn" field-type="object" required="true">

Cash collection summary. The object contains `purchasedCredits`, `grantedCredits`, `floatCredits`, and `cashCollected`.


</ResponseField>

<ResponseField name="creatorLiability" field-type="object" required="true">

Creator payout liability summary. The object contains `earnedCredits`, `paidOut`, and `netOwedCredits`.


</ResponseField>

<ResponseField name="approx" field-type="boolean" required="true">

Indicates whether any all-time scan hit the 50,000-row cap.


</ResponseField>

## GET `/api/admin/billing/top-workflows`

Rank workflows by billing activity over a selected time window. Use pagination to page through larger result sets.

### Query parameters

<ParamField query="range" param-type="string" required="false">

Time range to evaluate. Accepted values are `today`, `7d`, `30d`, and `all`. The default is `30d`. The `today` boundary uses the IST calendar day.


</ParamField>

<ParamField query="limit" param-type="string | integer" required="false">

Maximum number of items to return. The default is `10`. Values are clamped to the range `1` through `100`.


</ParamField>

<ParamField query="offset" param-type="string | integer" required="false">

Pagination offset. The default is `0`. Values are clamped to the range `0` through `100000`.


</ParamField>

<ParamField query="excludeTest" param-type="string" required="false">

Pass `1` or `true` to exclude users flagged as `is_test_account` from the ranking.


</ParamField>

### Example request

<CodeGroup tabs="cURL,JSON response">

```bash
curl -X GET "http://localhost:3000/api/admin/billing/top-workflows?range=7d&limit=3&offset=0&excludeTest=1" \
```

## GET `/api/admin/billing/users/search`

Search users by name, email, or exact UUID before requesting a per-user billing summary.

### Query parameters

<ParamField query="q" param-type="string" required="false">

Search term. Empty or missing values return an empty `items` array. If the value is a valid UUID, the API performs an exact match lookup. Otherwise, the API performs a case-insensitive `ILIKE` search on `full_name` or `email` and returns up to 20 results.


</ParamField>

### Example request

<CodeGroup tabs="cURL,JSON response">

```bash
curl -X GET "http://localhost:3000/api/admin/billing/users/search?q=alice%40example.com" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.example-admin-token" \
  -H "Accept: application/json"
```

```json
{
  "items": [
    {
      "id": "6f1d9b57-7cc7-4e8b-8fcb-06ff3d9059b1",
      "full_name": "Alice Nguyen",
      "email": "alice@example.com"
    }
  ]
}
```

</CodeGroup>

### Response fields

<ResponseField name="items" field-type="array" required="true">

Matching users. Each item includes `id`, `full_name`, and `email`.


</ResponseField>
