## Overview

Track reader-facing Gravity platform changes in one place, with the newest release first. Each entry highlights what changed and what it means for developers and operators running the platform.

<Update label="2026-03" description="v0.1.0" tags={["feature", "improvement", "bugfix"]}>

### New features

- **Per-service semantic versioning** — Web, API, and AI service now version independently, so each service can ship on its own cadence. Commit markers such as `[major]`, `[minor]`, and `feat:` trigger the correct bump automatically, and development builds receive pre-release tags such as `0.1.0-dev.20260307.a1b2c3d`. See [Service Versioning](/service-versioning).
- **CI/CD pipelines for all services** — Every service now runs build, lint, versioning, Docker image publishing, and GitHub Release creation on pushes to `main` and `dev`. Operators get consistent container images in GitHub Container Registry with versioned tags for deployment and rollback. See [CI/CD Pipelines](/ci-cd-pipelines) and [Docker Images and Packaging](/docker-images-and-packaging).

### Updates

- **Web app migrated to Remix v2** — The frontend moved from React Router v7 to Remix v2 and upgraded from Tailwind CSS v3 to v4. This changes the application shell to Remix's routing and rendering model and aligns future frontend work to that stack. See [Frontend Application Shell](/frontend-application-shell).
- **Simplified Docker builds** — The web service Dockerfile now uses a two-stage build and `npm` instead of `pnpm`. This reduces build complexity and makes container packaging easier to maintain. See [Docker Images and Packaging](/docker-images-and-packaging).

### Bug fixes

- **Fixed Docker build for shared TypeScript config** — Web image builds no longer fail when `tsconfig.base.json` lives outside the Docker build context. The pipeline now copies the shared config into the build context before building the image.

</Update>
