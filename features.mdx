## Overview

Gravity lets you discover, create, run, monetize, and improve workflow-based agents. Buyers can run published agents and schedule recurring work, while builders can publish agents, earn revenue, respond to requests, and compete for funded bounties.

<Callout kind="info">

Agents can collect structured inputs, connect to external tools, run on demand or on a schedule, and report execution results with specific status and error details.

</Callout>

### Publish an agent

Gravity inspects the workflow template before publication so builders can correct missing setup fields and understand how the workflow behaves. The resulting agent includes the inputs consumers must provide and the outputs they can expect.

<Callout kind="tip">

Review generated descriptions, categories, inputs, and outputs before publishing. Clear consumer inputs reduce failed runs and support requests.

</Callout>

### Subscription lifecycle

Paid plans require checkout, while free plans become active without payment processing. You can cancel a subscription at the end of its current billing period, so existing access remains available until the period ends.

### Earnings and referrals

Creator earnings track money generated by agent usage. Referral earnings are calculated from the earnings of builders who joined through your share link, with monthly payouts during the first year.

## Schedule and monitor runs

### Scheduled agents

Schedule an agent for recurring runs when the same workflow needs to operate over time. Activating a schedule estimates the remaining cost in the current cycle, checks that your credit entitlements can cover it, and creates a soft reservation for the expected usage.

Pausing or unsubscribing from the schedule releases the reservation. This keeps reserved credits aligned with the schedules that are still active.

<Callout kind="tip">

Check the estimated remaining-cycle cost before activating a schedule. A schedule must be affordable against your available credit entitlement before it can start.

</Callout>

### Paused-run handling

A paused execution reports why it is waiting instead of showing a generic approval message. Gravity classifies paused runs as one of the following:

- **`approval`**: A human approval step is waiting for a decision.
- **`delay`**: A timer or wait period must finish before execution continues.
- **`agent`**: An AI-agent waitpoint is holding the execution.
- **`unknown`**: The platform cannot identify a more specific wait condition.

The UI uses the classification to show messaging that matches the actual state of the run.

### Execution error reporting

Failed runs distinguish resource and execution failures so you can identify the appropriate next step. Gravity reports separate error types for memory limits, log size limits, and quota limits instead of reducing them to a generic internal error.

Timeout failures preserve information about the step that failed. Use that step context to locate the operation that exceeded the allowed execution time.

## Review and improve agent quality

### Agent review and quality feedback

Admins can review submitted agents through an automated verification pipeline. The review covers behavioral checks, code checks, network checks, guardrail checks, and AI reviewer checks.

Admins can edit finding severity before sending a report. Sending the report also rejects the submission, so the report represents the final review decision for that submission.

Builders can mark individual findings as fair or unfair and add notes to explain their feedback. Admins can re-run the quality review using the stored submission data when they need to reassess an agent.

<Callout kind="info">

Treat quality findings as actionable feedback. Review each finding, add context for disputed results, and update the workflow before submitting again.

</Callout>

## Connect external tools

### Connections and integrations

Connect the external services your agents need through OAuth, API keys, or Activepieces connections. Gravity detects required connections from the workflow and guides you through the setup before a run starts.

OAuth flows can use Gravity-managed configuration or custom OAuth client credentials when a service requires your own client registration. Once a connection is established, the agent can use it without asking you to enter credentials for every run.
