## Overview

This page documents the NestJS backend service routes currently implemented in the AIGravity core repository. The code analysis found a public health endpoint at `GET /health`, plus bounty creation, bounty retrieval, and Razorpay pay-to-post funding endpoints.

<Callout kind="info">

Implementation details on this page were derived from code analysis of `apps/api/src/main.ts`, `apps/api/src/app.module.ts`, and `apps/api/src/health/health.controller.ts`, rather than direct file reads through the docs repository tool.


</Callout>

<Callout kind="alert">

The repository README mentions `GET /api/health`, but the code currently implements `GET /health`. No global prefix is configured, so the `/api` path is not active.


</Callout>

### POST `/api/bounties`

Create a bounty for a chat session. When Razorpay is enabled and the bounty amount is greater than zero, the bounty is created with `pending_payment` status and `paymentRequired: true` — the client must complete payment via the pay-to-post flow before the bounty goes live. When Razorpay is disabled or the amount is zero, the bounty is immediately `open`. If the session already has an `open` or `pending_payment` bounty, the existing bounty is returned without creating a new one.

<ParamField body="auth" param-type="string" required="true" show-location="false">

Bearer token required via `SupabaseAuthGuard`. The JWT `sub` claim is extracted as the `userId`.


</ParamField>

<ParamField body="title" param-type="string" required="true" show-location="false">

Bounty title.


</ParamField>

<ParamField body="summary" param-type="string" required="true" show-location="false">

</ParamField>

<ParamField body="amount" param-type="number" required="true" show-location="false">

Prize amount in major units. For example, `500` represents Rs.500.


</ParamField>

<ParamField body="currency" param-type="string" required="true" show-location="false">

Currency code. Legacy `RS` is accepted and normalized to `INR`.


</ParamField>

<ParamField body="sessionId" param-type="string (UUID)" required="true" show-location="false">

Chat session UUID this bounty belongs to.


</ParamField>

### POST `/api/bounties/{id}/pay/verify`

Verifies the HMAC-SHA256 signature from a completed Razorpay Checkout, marks the order as paid, and transitions the bounty from `pending_payment` to `open`. Called by the browser immediately after payment success. The Razorpay webhook serves as a backstop if the browser call fails after payment.

<ParamField body="auth" param-type="string" required="true" show-location="false">

Bearer token required.


</ParamField>

#### Path parameters

<ParamField path="id" param-type="string (UUID)" required="true">

Bounty UUID being funded. The server uses this value for logging; it looks up the order by `razorpayOrderId` from the request body.


</ParamField>

#### Request body

<ParamField body="razorpayOrderId" param-type="string" required="true" show-location="false">

Razorpay order identifier in the `order_xxx` format from the `/pay/order` response.


</ParamField>

<ParamField body="razorpayPaymentId" param-type="string" required="true" show-location="false">

Razorpay payment identifier in the `pay_xxx` format from the Checkout success handler.


</ParamField>

<ParamField body="razorpaySignature" param-type="string" required="true" show-location="false">

HMAC-SHA256 signature of `order_id|payment_id` from the Checkout success handler.


</ParamField>

#### Example request body

<CodeGroup tabs="JSON">

```json
{
  "razorpayOrderId": "order_PqRsTuVwXyZ",
  "razorpayPaymentId": "pay_AbCdEfGhIjKl",

}
```

</CodeGroup>

#### Example request

<CodeGroup tabs="cURL">


</CodeGroup>

### POST `/api/webhooks/razorpay`

Processes Razorpay payment events for both bounty orders and credit orders. For `payment.captured` and `order.paid` events, the handler checks bounty orders first, then falls back to credit orders. For `payment.failed` events, it marks the corresponding order as failed if it is still pending.

<ParamField body="auth" param-type="string" required="true" show-location="false">

No authentication required. Razorpay webhook signature verification is used instead.


</ParamField>

#### Path parameters

<ParamField body="path parameters" param-type="none" required="false" show-location="false">

</ParamField>

</ParamField>

## Bounty lifecycle states

<Callout kind="info">

| Status | Description |
| --- | --- |
| `pending_payment` | Created, awaiting Razorpay payment. Hidden from the public bounty list. |
| `open` | Live and accepting submissions. |
| `awarded` | A winner has been chosen. |
| `expired` | Past the expiry date. |


</Callout>

## Pay-to-post flow

Pay-to-post adds a payment step between bounty creation and public listing when Razorpay funding is required. The client creates the bounty, opens Razorpay Checkout with the generated order, then verifies the completed payment so the bounty moves to `open`.

<Callout kind="info">

- `POST /api/bounties` is idempotent per chat session. If the session already has an `open` or `pending_payment` bounty, the API returns the existing bounty.
- `POST /api/bounties/{id}/pay/order` is idempotent on `razorpay_order_id` through a database `UNIQUE` constraint.
- `POST /api/bounties/{id}/pay/verify` is idempotent. `markBountyFunded` is scoped to `status='pending_payment'`, so a second call is a no-op.


</Callout>
