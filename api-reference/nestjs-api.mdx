## Agent verification warmup

### POST `/agents/verify-warmup`

Triggers a background warmup of the agent verification pipeline so that subsequent verification requests start faster. The endpoint returns immediately without waiting for the warmup to complete.

This is a fire-and-forget call: the server primes the verification components (including the piece catalog, LLM clients, content safety guardrails, and URL safety feeds) in the background while the caller continues with other work.

<ParamField body="method" param-type="string" required="true" show-location="false">

`POST`


</ParamField>

<ParamField body="path" param-type="string" required="true" show-location="false">

`/agents/verify-warmup`


</ParamField>

<ParamField body="request body" param-type="none" required="false" show-location="false">

None. This endpoint does not accept a request body.


</ParamField>

### Example request

<CodeGroup tabs="cURL">

```bash
curl -i -X POST http://localhost:3001/agents/verify-warmup
```

</CodeGroup>

### Response

Returns `202 Accepted` immediately, indicating that the warmup has been started in the background.

<CodeGroup tabs="JSON">

```json
{
  "warming": true
}
```

</CodeGroup>

<ResponseField name="warming" field-type="boolean" required="true">

Returns `true` to confirm that the warmup process has been initiated.


</ResponseField>

## Agent verification prewarm

### POST `/agents/verify-prewarm`

Pre-runs the behaviour analysis stage of the verification pipeline on a submitted workflow and caches the result. When the builder later triggers a full verification, the cached result is reused instead of re-running the analysis from scratch.

This is a fire-and-forget call: the server begins the analysis in the background and returns immediately. The cache is keyed by the workflow's content hash and expires after 30 minutes.

<ParamField body="method" param-type="string" required="true" show-location="false">

`POST`


</ParamField>

<ParamField body="path" param-type="string" required="true" show-location="false">

`/agents/verify-prewarm`


</ParamField>

### Request body

<ParamField body="workflowJson" param-type="string" required="true">

The workflow JSON to pre-analyse. This should be the same workflow JSON that will be submitted during the full verification step.


</ParamField>

### Example request

<CodeGroup tabs="cURL">

```bash
curl -i -X POST http://localhost:3001/agents/verify-prewarm \
  -H "Content-Type: application/json" \
  -d '{"workflowJson": "{\"trigger\": {}, \"steps\": []}"}'
```

</CodeGroup>

### Response

Returns `202 Accepted` immediately, indicating that the prewarm analysis has been started in the background.

<CodeGroup tabs="JSON">

```json
{
  "prewarming": true
}
```

</CodeGroup>

<ResponseField name="prewarming" field-type="boolean" required="true">

Returns `true` to confirm that the prewarm analysis has been initiated.


</ResponseField>

## Notes

The NestJS bootstrap code enables CORS for origin `http://localhost:3000` and sets `credentials` to `true`. The application listens on port `3001`, so all endpoints are available at `http://localhost:3001` in the current local configuration.
