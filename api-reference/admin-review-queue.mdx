## Overview

Admin endpoints for managing the agent review queue. Each submission now carries an agent-ranker quality score from 0 to 100 captured at submission time, and detailed records include the full per-use-case score breakdown and pre-publish E2E test run history.

<Callout kind="info">

All admin endpoints require both JWT authentication and administrative privileges. Requests without a valid admin JWT return `401 Unauthorized` or `403 Forbidden`.


</Callout>

## Endpoints

### GET /api/agents/admin/pending-reviews

Returns a list of agent submissions in the admin review queue. Each row includes the agent-ranker quality score captured at submission time when available. Filter by status to view rejected submissions from the archive.

#### Query parameters

<ParamField query="status" param-type="string" required="false" enum="pending,rejected">

Filter by review status. Use `pending` to return the active review queue. Use `rejected` to return rows from the rejected reviews archive.

</ParamField>

#### Request example

<CodeGroup tabs="cURL,JavaScript">

```bash

  --url "https://api.aigravity.com/api/agents/admin/pending-reviews?status=pending" \
```

### GET /api/agents/admin/pending-reviews/{id}

Returns the full detail of a single agent submission, including the quality scoring breakdown and pre-publish E2E test run history.

#### Path parameters

<ParamField path="id" param-type="string" required="true">

Review row UUID.

</ParamField>

#### Request example

<CodeGroup tabs="cURL,JavaScript">


##### Quality scoring fields

<ResponseField name="rankerScore" field-type="number | null" required="false">

Headline quality score captured at submission time. Values range from 0 to 100. Returns `null` when the ranker was unconfigured, unreachable, or the agent was ineligible for all use cases.

</ResponseField>

<ResponseField name="rankerScores" field-type="object | null" required="false">

Per-use-case score breakdown keyed by use case ID. Each value contains explainability data such as eligibility, display score, rank, candidate count, cold start status, probability of being the best candidate, reasons, and hard failures.

</ResponseField>

<ResponseField name="rankerBundleVersion" field-type="string | null" required="false">

</ResponseField>

<ResponseField name="e2eRuns" field-type="array" required="false">

The `rankerScores` object provides explainability data. Each key is a use case ID, and each value contains fields such as `eligibility`, `displayScore`, `rank`, `candidates`, `coldStart`, `probabilityBest`, `reasons`, and `hardFailures`.


</Callout>

### POST /api/agents/admin/pending-reviews/{id}/approve

Approves a pending agent submission, publishing the agent to the marketplace. The HTTP interface is unchanged, but the approval flow now carries the review-time quality score forward to the published agent metadata.

#### Path parameters

<ParamField path="id" param-type="string" required="true">

Review row UUID.

</ParamField>

#### Request example

<CodeGroup tabs="cURL,JavaScript">

```bash
curl --request POST \
  --url "https://api.aigravity.com/api/agents/admin/pending-reviews/7d4a1d2c-7a34-4ee5-b4ec-f3dc20d0c281/approve" \
  --header "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.admin_example_q7m4r2" \
  --header "Content-Type: application/json"
```

```javascript
const reviewId = "7d4a1d2c-7a34-4ee5-b4ec-f3dc20d0c281";

const response = await fetch(
  `https://api.aigravity.com/api/agents/admin/pending-reviews/${reviewId}/approve`,
  {
    method: "POST",
    headers: {
      Authorization: "Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.admin_example_q7m4r2",
      "Content-Type": "application/json"
    }
  }
);

const data = await response.json();
console.log(data);
```

</CodeGroup>

#### Response

A successful response confirms that the review was approved and the agent was published.

<CodeGroup tabs="200 OK">

```json
{
  "success": true,
  "status": "approved",
  "reviewId": "7d4a1d2c-7a34-4ee5-b4ec-f3dc20d0c281",
  "publishedAgentId": "agt_pub_4rk8m2q1"
}
```

</CodeGroup>

<Callout kind="info">

If the submission carried a ranker quality score at submission time, that score is carried forward to the published workflow metadata. This keeps the published agent score aligned with the review-time score computed with E2E run data instead of recalculating at publish time.

This carry-over is best-effort. Failures are logged, but they do not fail the approval request.


</Callout>

#### Error responses

| Status | Meaning |
| --- | --- |
| `401` | Missing or invalid JWT |
| `403` | Authenticated user lacks admin privileges |
| `404` | Review row was not found |
